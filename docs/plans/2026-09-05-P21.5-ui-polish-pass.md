# P21.5 Plan: UI Polish Pass — Shell Ergonomics, Button Semantics, Inspector Density & Viewport De-Cluttering

**Status:** Implementation Specification  
**Authority:** Follows `Design-Plan(P21+).md` and `theme.md`; addresses implementation drifts and visual noise identified in the live P21 shell build.  
**Objective:** Transform the current functional scaffolding into an intuitive, calm, self-explanatory DCC interface by eliminating visual noise, restoring proper interactive hierarchies, fixing Inspector routing, and matching the ratified reference mocks.

---

## 1. Root-Cause Analysis & Polish Objectives

Inspecting the live implementation against the ratified target PNGs reveals five systematic issues causing visual noise and cognitive overload:

1. **"Outline Disease" (Button Hierarchy Breakdown):** Inactive buttons, active tools, status badges, and tree rows all share a loud 1px accent stroke. Because everything is outlined, nothing reads as primary or active.
2. **Broken Segmented Controls:** `[Scene | Camera]`, `[Plan | 3D]`, and `[Layout | Arrange]` render as disconnected, standalone square buttons with gaps, rather than unified pill containers.
3. **Viewport Intrusion:** A massive floating white instruction banner sits directly over the center canvas, obscuring drawing areas, room walls, and camera nodes.
4. **Inspector Bloat & IA Leakage:** Permanent camera/lighting debug panels are glued to the bottom of the Inspector regardless of selection, and 2D Layout "Place" tools leak into the 3D Inspector. Furthermore, transform coordinates ($X, Y, Z$) are stacked as three bulky, full-width text inputs.
5. **Light Mode Contrast Vibration:** The terracotta/orange accent outline vibrates harshly against the warm `#F5F3EE` / `#F4F1EA` paper background.

### Slice 1: Row 1 & Row 2 Geometry, Segmented Controls & Button Hierarchy

* **Buttons in Row 2:** Fixed `height: 28px`, `padding: 0 8px`, `border-radius: var(--editor-radius-sm, 4px)`.

#### 1.2 True Enclosed Segmented Controls
Replace loose, outlined button pairs with canonical segmented containers for:
1. `[ Scene | Camera ]`
2. `[ Plan | 3D ]`
3. `[ Layout | Arrange ]` (Scene Plan only)

**Container Styling:**

#### 1.3 Strict Four-Tier Button Grammar
Stop applying accent borders to inactive buttons. Enforce these universal rules across Row 2, sidebars, and panels:

| Button State | Background | Border | Text Color | Usage |
|---|---|---|---|---|
| **Ghost (Default)** | `transparent` | `none` (or `1px solid transparent`) | `var(--editor-text-secondary)` | Standard tools, secondary actions (`Undo`, `Redo`, `View`) |
| **Hover** | `var(--editor-bg-hover)` | `none` | `var(--editor-text-primary)` | Pointer hover over any ghost button |
| **Active / Toggled On** | `var(--editor-accent-soft)` | `1px solid var(--editor-accent-border)` | `var(--editor-text-primary)` | Currently active tool (`Select`, `Move`, `Observer`, `Snap`) |
| **Primary CTA** | `var(--editor-accent)` | `none` | High-contrast white | `▶ Preview`, `Save Changes` |

---

#### 2.4 Scene 3D Gizmo De-Cluttering (Single-Ended Handles) — pinned 2026-09-05

* **Problem:** The Move and Scale gizmos render **double-headed**: three.js r175 `TransformControls` places an arrowhead (Move) / grip cube (Scale) at **both** the `+` and the `−` end of every axis. Each axis reads twice as busy, and the negative-end decoration adds no capability (a drag from either side moves the same axis).
* **Fix:** Show one handle per axis — arrow at the `+` tip for Move, grip cube at the `+` tip for Scale — and hide the negative-end mesh on each axis.
* **Safety:** Cosmetic-only. Three.js keeps drag targets in a separate invisible `picker` hierarchy, so hit-testing, snapping, hover/active states, and all behavior are untouched (verified before pinning).
* **Files:** `gizmo/EditorTransformControlsHost.svelte` (single `getHelper()` site — guarded cosmetic walker beside `applyEditorGizmoPalette`, matching tip meshes by local-position sign and skipping the axis line at the origin; runs once at mount) and `styles/scene-palette.ts` (function lives beside the existing palette pass). Unit test asserts all six axes remain present.
* **Notes:** three is pinned in the lockfile; a future version bump needs a visual re-check. Applies consistently to every context of the shared host (Scene, Layout, Camera-handle). **Overlap check:** no P21.5 slice or shipped doc owns gizmo geometry — P21.2 keeps the gizmo untouched (`viewport/gizmo/cube untouched`); P3.2 (shipped) recolored gizmo materials only. This item is additive to Slice 2's de-cluttering intent, not a collision.

### Slice 3: Inspector Overhaul & Selection Isolation

#### 3.1 Compact Single-Row Coordinate Chips ($X, Y, Z$)
* **Problem:** Transform coordinates currently stack vertically as three full-width input boxes with huge padding, forcing vertical scrolling for basic property checks.
* **Fix:** Unify Position, Rotation, and Scale into single horizontal 3-column rows matching DCC standards:

```text
TRANSFORM
Position (m)
┌─────────────────────────────────────────────────────────────┐
│ [X]  1.435       │ [Y]  0.000       │ [Z]  1.909            │
└─────────────────────────────────────────────────────────────┘
Rotation (deg)
┌─────────────────────────────────────────────────────────────┐
│ [X]  0.0°        │ [Y]  15.0°       │ [Z]  0.0°             │
└─────────────────────────────────────────────────────────────┘
```

**Field Specification:**
* Container: `height: 28px`, `display: grid; grid-template-columns: 1fr 1fr 1fr; gap: 6px`.
* Sub-item: Flex container with an inline colored chip (`width: 18px; height: 18px; font-size: 10px; font-weight: 700; border-radius: 3px`):
  * $X$: `background: rgba(240, 82, 82, 0.15); color: var(--editor-axis-x, #F05252)`
  * $Y$: `background: rgba(69, 200, 120, 0.15); color: var(--editor-axis-y, #45C878)`
  * $Z$: `background: rgba(59, 130, 246, 0.15); color: var(--editor-axis-z, #3B82F6)`
* Input: Borderless text box with `font-variant-numeric: tabular-nums; font-size: 12px`.

#### 3.2 Strict Selection Routing (Purge Permanent Debug Panels)
* Remove the permanently mounted `Camera (Pan on, Grid on, Floor)` and `Lighting (Bright, Visitor, Ambient, Directional)` panels from `EditorInspector.svelte`.
* **Routing Rules:**
  * **Zero Selection:** Render only the lightweight *Empty Selection Primer* (`Create your first room...` or `Select an entity to inspect`).
  * **Camera Node Selected:** Render node name, pose, FOV, look-at target, timing summary.
  * **Camera Connection Selected:** Render undirected endpoints (`Camera A`, `Camera B`), bidirectional duration, derived speed, path spline type.
  * **3D Object Selected:** Render entity name, Transform ($X/Y/Z$), Placement asset, PBR material properties.
  * **Layout Mode:** In Scene 3D, remove 2D layout drafting tools (`Place: Door, Window, Box...`) from the Inspector.

#### 3.3 Relocate Viewport Lighting & Floor Overrides
* Floor color, session ambient lighting sliders, and viewport grid toggles belong in the **Viewport View Menu** (`Row 2 → View ▾`) or as direct secondary controls in the bottom status bar, never occupying vertical space in the selection Inspector.

### Slice 4: Light Mode Contrast & Token Calibration

#### 4.1 De-Saturate the Light Theme Accent
* In `theme.svelte.ts` / `tokens.css`, calibrate the light-theme chrome accent family so it no longer vibrates against warm backgrounds:
  * Inactive buttons: `border: none; background: transparent`.
  * Active toggles: Use a soft terracotta tint (`--editor-accent-soft: rgba(217, 72, 38, 0.10)`), with text in deep sienna (`#B43B1E`).
  * Active selection in 3D/Plan remains brand blue (`#2F8CFF`).

#### 4.2 Quiet Hairline Borders
* Change light mode panel borders from dark/red outlines to quiet neutral hairlines:
  ```css
  --editor-border-subtle: rgba(0, 0, 0, 0.08); /* or #E2DDD5 */
  --editor-border-normal: rgba(0, 0, 0, 0.14); /* or #D4CEBF */
  ```
* Panels achieve separation through clean surface tone steps, not thick border lines.

#### 4.3 Typography & Tabular Numerals
* Apply `font-variant-numeric: tabular-nums;` to all coordinates, dimensions, angles, and timecodes.
* Enforce three font sizes across the Inspector:
  * **Section Headers:** `11px`, uppercase, `font-weight: 600`, letter-spacing `0.05em`, color `var(--editor-text-muted)`.
  * **Property Labels:** `12px`, `font-weight: 400`, color `var(--editor-text-secondary)`.
  * **Values / Text Inputs:** `12.5px`, `font-weight: 500`, tabular nums, color `var(--editor-text-primary)`.
