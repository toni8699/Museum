## Goal

Make catalogue asset placement room-agnostic in the greenfield H1 editor. The
pre-H1 "Paris-oriented" placement rule is a frozen-relic assumption that leaks
into H1 through the shared placement path: `beginAssetPlacement` preselects
`paris`, the click handler only accepts a `paris` floor, and the created entity
is stamped `roomId: 'paris'`. A boot-empty H1 project has no `paris` room, so
catalogue placement is unreachable there. This slice resolves the target room
from the clicked floor — exactly like the already-room-agnostic shapes/lights
path — while `/museum/editor` keeps its Paris-oriented behavior byte-for-byte.

This is a scene-domain gesture only: it never mutates `project.layout`, adds
no history cross-domain coupling, and changes no placement semantics beyond
replacing a hardcoded id.

## Locked decisions

### Room-agnostic resolution mirrors shapes/lights

- The model path copies the primitive/light path: no room preselection, resolve
  `floorHit.roomId` from the click, convert the world point through
  `store.rooms.localPoint`, and stamp the entity with that room. No new
  placement semantics — only the hardcoded id is replaced.

### Relic stays frozen (gate on `isRelic`)

- Add a public `get isRelic(): boolean` over the existing private `relicMode`.
  When `store.isRelic`, `beginAssetPlacement` and `EditorSelection` keep the
  exact current behavior (preselect Paris, Paris-only floor match, "Place in
  Paris", "Click a placeable Paris floor", entity `roomId: 'paris'`). The
  room-agnostic branch runs only when `!store.isRelic`.

### `createPendingPlacementAt` takes the resolved room

- Change the signature to `createPendingPlacementAt(position: Vec3, roomId: MuseumRoomId)`
  and write `roomId` verbatim — the same `MuseumRoomId` typing the sibling
  `createPendingPrimitiveAt` and `SceneModelEntity.roomId` already use (a
  drafted id is passed as `MuseumRoomId`, the pre-existing type lie, not
  widened to `string` here). The caller decides: `'paris'` in relic mode,
  `floorHit.roomId` in H1. This keeps the mutator room-agnostic and the relic
  decision at the one shared call site.

### Live known-room predicate

- H1 passes `isKnownRoom = (id) => store.rooms.has(id)` to
  `findPlaceableFloorIntersection` instead of the Chopin `roomById` default, so
  drafted rooms are accepted. The default predicate stays for the relic
  (unchanged).

### CTA text is generic in H1

- `EditorInspector` button "Place in Paris" → "Place in room" (H1 only); H13DView
  hint → "Click a tagged museum-room floor to place". Relic strings untouched.

## Implementation steps

### 0. Turn the contracts into failing tests first

New `tests/lib/editor/h1/placement.test.ts` + additions to the
placement-cluster-mutator suite:

- `beginAssetPlacement` (non-relic): no `paris` preselection, status "Click a
  tagged museum-room floor to place …"; relic mode: preselection + Paris
  message unchanged.
- `createPendingPlacementAt(position, roomId)`: stamps the passed roomId (not
  `'paris'`).
- `findPlaceableFloorIntersection` accepts a drafted room when given
  `(id) => store.rooms.has(id)`; still rejects it under the default Chopin
  predicate.
- Live-rooms end-to-end (not a component mount — `EditorSelection` is a Svelte
  component vitest cannot mount): invoke the three calls the component makes —
  `findPlaceableFloorIntersection(intersections, undefined, livePredicate)` →
  `store.rooms.localPoint(floorHit.roomId, worldPoint)` →
  `createPendingPlacementAt(localPoint, floorHit.roomId)` — and assert one
  `scene` history entry with `entity.roomId` = the drafted room; the relic
  path still rejects a non-Paris floor.

**Existing-test churn (in scope, not a step-5 surprise):**
- `createFixtureEditorStore` builds non-relic stores (`createMuseumEditorStore({ document })`),
  so the Paris-behavior tests in `museum-editor-placement.test.ts`
  (`selectedRoomId === 'paris'` after arm; entity `roomId: 'paris'`) must be
  rebuilt against `createMuseumEditorStore({ document, relic: true })` (a relic
  fixture helper), keeping the relic assertions intact.
- Update the five existing `createPendingPlacementAt([…])` call sites for the
  new `roomId` argument: `museum-editor-placement.test.ts` (lines ~29, 38, 58,
  67) and `museum-editor-camera.test.ts` (line ~372).

### 1. Expose `isRelic`

- `museum-editor.svelte.ts`: add `get isRelic(): boolean { return this.relicMode; }`.
- Thread it to the mutator: add `readonly isRelic: boolean` to
  `EditorPlacementClusterMutatorHost` and forward it in the host object literal
  (`controller-hosts.ts`), so `beginAssetPlacement` can read `this.host.isRelic`.

### 2. Room-agnostic arm + commit

- `placement-cluster-mutator.beginAssetPlacement`: branch on `isRelic` —
  non-relic drops `selectRoom('paris')` and posts the tagged-floor message.
- `createPendingPlacementAt(position, roomId)`: write `roomId` (update the
  `museum-editor.svelte.ts` facade wrapper + the single caller).

### 3. Click resolution

- `EditorSelection.svelte` model branch: non-relic uses
  `findPlaceableFloorIntersection(intersections, undefined, (id) => store.rooms.has(id))`,
  `store.rooms.localPoint(floorHit.roomId, worldPoint)`, and passes
  `floorHit.roomId` to `createPendingPlacementAt`; relic keeps the `'paris'`
  path.
- H1 no-floor failure posts "Click a tagged museum-room floor to place"
  (mirroring the primitive/light branch), not the Paris string.

### 4. CTA text

- `EditorInspector.svelte` + `H13DView.svelte`: H1-only generic strings.

### 5. Regression + manual QA

- Full suite + `svelte-check` + production build.
- Manual: boot blank → draft a room → place a floor asset → entity lands in that
  room with one undo step; place a primitive/light (still tagged-floor);
  `/museum/editor` still shows "Place in Paris" and rejects a non-Paris floor;
  `/museum` visitor unchanged.
