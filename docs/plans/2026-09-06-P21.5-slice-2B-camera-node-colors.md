**Status:** Mini-slice brief (inserted between Slice 2 and Slice 3 — runs immediately after Slice 2).
**Authority:** P21.5 umbrella (`2026-09-05-P21.5-ui-polish-pass.md`) + `docs/components/camera-tour.md` + P12 topology/Sequence contract. Behavior-beats-pixels per P21 §1: no selection/history/ownership/transform/topology/timing change.
**Scope:** Presentation-only. Camera node fills/strokes/numerals/halos on the Plan canvas. No new controls, no model change, no `ExperienceDocument`, no behavior.
**QA: manual eye-test by owner** (acceptance below). Unit/check/build gates stay green but do not replace the eye-test.

## 1. Why (code-grounded defect, not taste)

Plan paper is theme-invariant (`--editor-plan-bg: #f5f3ee`, single root definition). Camera node ink is theme-variable: resting fill `var(--editor-bg-selected)`, strokes/fills from `accent*`, order-label halo `accent-pressed` (`PlanSvg.svelte:288-296`, `plan.css:42-46`). Across themes `bg-selected` swings from navy `#0c3766` (near-black at 24px) to porcelain `#fbe9e4` (effectively invisible on paper at ~1:1 contrast). Nodes must match the spline they sit on (`--editor-camera-edge-stroke` = `#2F8CFF` at 60%), not the shell theme.

Note: the `bg-selected` fill assignment arrived inside the Slice 2 tree without a §2.x plan item. This slice replaces that rule with invariant tokens; if 2B stalls, revert the one-liner (`--editor-camera-node-fill` back to `#0c3766`) rather than shipping theme-variable ink.

Two claims from the proposal are kept out of this brief for lack of code evidence: red sequence numerals (order labels render `text-primary`) and a terracotta selected-center on unsequenced nodes (no `free+selected` fill rule exists). The confirmed contrast defect above is sufficient scope. White-on-`#2F8CFF` is ~3.5:1, not 7:1 as the proposal states — acceptable for bold 11px map numerals with a halo stroke, but the brief claims no more.

## 2. Adopted direction: Option 1 (blueprint standard) with four amendments

Golden rule: **color communicates role; selection uses halos, never fill inversion.**

| Node state | Diameter | Fill | Border / stroke | Numeral / glyph | Halo |
|---|---|---|---|---|---|
| Sequenced resting | 24px | `#2F8CFF` | 1.5px `#FFFFFF` | white bold tabular | none |
| Sequenced selected | 28px | `#1976DF` | 2px `#FFFFFF` | white bold tabular | 3px `rgba(47,140,255,.35)` outer ring |
| Unsequenced resting | 24px | paper/transparent | 2px dashed `#10B981` | emerald dot/glyph | none |
| Unsequenced selected | 28px | `rgba(47,140,255,.12)` | 2px solid `#10B981` | emerald dot/glyph | 3px `rgba(47,140,255,.35)` outer ring |

Amendments to the proposal as written:

1. **No start pip/badge.** There is no start concept in the model; order numeral "1" already communicates it. No third glyph system.
2. **Resting unsequenced is dashed** (solid when selected). The proposal's matrix hedged "dashed/solid" — dashed reads "not in tour" at a glance against solid filled sequenced nodes.
3. **Flat primitives, not `<g>` groups.** `PlanSvg` renders flat circle/text primitives (the §2.5 pill `<g>` is the sole exception). Implement the halo as an extra circle primitive behind the node body, not a grouped marker rewrite. Projection emission (`plan-camera-projection.ts:196-225`) stays structurally as-is unless the implementer shows a grouping need.
4. **Hit radius stays stable** across the 24→28px selected growth — verify node picking does not use the visual radius before landing size-as-selection.

## 3. Tokens (invariant spatial palette — never per-theme)

Precedent: `--editor-axis-*` are invariant hexes for spatial meaning. Place beside them, not in theme blocks:

```css
--editor-plan-node-seq-bg:          #2F8CFF;
--editor-plan-node-seq-bg-active:   #1976DF;
--editor-plan-node-seq-border:      #FFFFFF;
--editor-plan-node-seq-text:        #FFFFFF;
--editor-plan-node-unseq-border:    #10B981;
--editor-plan-node-unseq-glyph:     #10B981;
--editor-plan-node-unseq-bg-active: rgba(47, 140, 255, 0.12);
--editor-plan-node-halo:            rgba(47, 140, 255, 0.35);
```
