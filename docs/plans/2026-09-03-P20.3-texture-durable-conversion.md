# P20.3 (S3) — Texture durable-conversion slice brief

**Date:** 2026-09-03 · **Plan:** [P20 Project Asset Registry + R2](2026-08-19-P20-Project-assets-registry-R2.md) S3

**Status:** **shipped 2026-09-04**; the P20.1 release gate was closed by the local live smoke (local API + local Postgres + real R2)

**Baseline:** P20 S0 contract + locally complete P20.1 API and P20.2 Spatial registry integration

**Purpose:** explicitly convert session/package texture bytes into ready project assets, replace only their Scene texture URI, clear the cloud-Save blocker truthfully, and keep package export portable.

## Status / closeout (2026-09-03)

P20.3 is implemented locally:

- eligible cached `/local/...` and `/textures/package-...` textures expose an
  explicit per-row `Save to project` action;
- register → upload → verified-ready metadata → logical cache prime → one
  guarded, undoable URI replacement reuses the existing editor seams;
- failed uploads retain the asset ID/bytes for retry, while ready upload
  metadata retries replacement without another PUT;
- cloud Save rechecks current-project readiness at capture and final submit;
  package export resolves cache first, then a verified authenticated logical
  asset fetch, while retaining the portable package rewrite.

P20.4 still owns automatic refresh/Load-time resolution and deployed fidelity
smoke. No live R2 smoke or production secret change was made here.

---

## 1. Outcome and cut line

For an authenticated owned project:

```text
/local/... or /textures/package-... texture
→ existing BinaryTextureStore bytes
→ P20.1 register + upload to ready
→ one undoable URI replacement
→ /project-assets/{assetId}
→ normal P19 Save
```

Conversion is explicit per texture from the existing Spatial Textures grid.
Cloud Save never uploads implicitly. Save stays blocked while any local/package
URI remains, while an upload is pending, or while a logical project-asset URI
is not proven ready for the current owned project.

P20.3 also lets package export resolve a ready logical project asset through
the authenticated API when its bytes are not already cached. The package keeps
the existing manifest and package-local URI rewrite; it contains no API/R2 URL
and needs no later authentication.

P20.4 owns automatic refresh/Load-time byte resolution and the deployed
Save → refresh → Load → render smoke. No batch converter, automatic Save,
schema change, final Assets workspace, GLB, delete/GC, dedup, background upload,
or guest binary handoff.

## 2. Current seams to reuse

| Surface | Existing seam | P20.3 use |
| --- | --- | --- |
| Eligibility | `isPackageRewriteUri` + `BinaryTextureStore.getEntry/resolve` | Convert only `/local/...` and package-rewrite URIs whose bytes exist now |
| API and ownership | P20.2 `projectAssetsAvailable`, `beginProjectAssetMutation`, `ProjectApi.registerAsset/uploadAsset/loadAssetContent` | Reuse the current owned-project, abort, stale-token, validation, and retry boundaries |
| Integrity/cache | `sniffImageMime`, `registerVerifiedProjectAsset`, `BinaryTextureStore.register` | Validate source and fetched bytes; prime the logical URI before document mutation |
| Scene mutation | `EditorMaterialResourceMutator` document-transaction host | Replace one texture row's `uri`; preserve its `id`, `name`, and every `baseTextureId` binding |
| Cloud gate | `computeCloudSaveBlocker(document, isReadyProjectAsset)` | Supply current-project ready evidence; do not weaken local/package or safe-URI rules |
| Save | `captureValidatedSaveSnapshot` + final `submitSaveSnapshot` re-check | Apply the same readiness-aware predicate at both boundaries |
| Package export | `buildPackage` injected `resolveBytesByUri`; `EditorStore.exportPackage` | Resolve cache first, then a narrow authenticated project-asset fallback |
| UI | `EditorAssetLibrary.svelte` texture cards and S2 pass-through props | Add one `Save to project` / retry action on eligible texture rows |

`SceneTextureAsset` remains exactly `{ id, name, uri }`. A successful
conversion changes only `uri` from the source form to
`/project-assets/{serverUuid}`.

## 3. Decisions

### D1 — Explicit per-texture conversion; Save remains side-effect free

An eligible local/package texture card shows `Save to project` only when the
current project is authenticated and owned and its exact source URI has bytes
in `BinaryTextureStore`. Ineligible, missing-byte, static, and already-logical
textures do not offer conversion.

Pressing Save with blockers reports the existing failure and directs the user
to Assets → Textures. It does not register rows, upload bytes, open OAuth, or
start a batch job. This keeps retry and history scoped to one texture.

### D2 — Reuse S2 upload orchestration; distinguish create from replace

Extend the current bounded `ProjectAssetRetry` record with the completion
intent:

```ts
intent:
  | { kind: 'register' }
  | { kind: 'replace'; textureId: string; sourceUri: string }
```

Both paths keep the same project ID, server asset ID, name, and copied bytes.
S2's new-cloud-file path finishes with existing texture registration. S3's
conversion path finishes with guarded URI replacement. Do not add a second
upload controller or registry state store.

For conversion:

1. capture `{ projectId, textureId, sourceUri }` plus bytes;
2. re-check current ownership, exact texture identity/URI, byte MIME, and size;
3. register metadata and upload to the same retained asset ID;
4. require validated `ready` metadata for the same project/asset/bytes;
5. upsert that metadata into the current contextual `projectAssets` state;
6. prime `/project-assets/{assetId}` with the verified bytes;
7. replace the URI through one existing Scene transaction;
8. refresh the registry list best-effort.

The validated upload response is sufficient ready evidence even if the
follow-up list refresh fails. Project/session invalidation clears that evidence.

### D3 — Add one guarded URI-replacement command

Add the smallest store/mutator command:

```ts
replaceTextureUri(textureId, expectedUri, nextUri): boolean
```

It rejects mutation/interaction blocks, missing texture ID, stale
`expectedUri`, unsafe `nextUri`, and a no-op. Otherwise it opens one document
transaction, changes only that texture row's URI, and commits. The texture's
scene-local ID and material bindings remain unchanged; selection does not
change.

Conversion does not register a second `SceneTextureAsset`. Undo restores the
source URI and cloud-Save blocker; redo restores the logical URI. The registry
row survives both.

### D4 — Preserve source bytes for undo during the project session

Prime the logical URI without deleting the source entry. Same-project asset
operations must not prune converted source aliases that history may restore.
Keep them until project replacement or unmount performs bounded cache cleanup.
This is session-only memory, never project truth.

No history-stack inspection or persistent cache is added. If retained aliases
become a measured memory problem, a later change can expose history-reachable
URIs to `clearExcept`; P20.3 does not need that machinery.

### D5 — Ready evidence is current-project metadata, not cache presence

Define one app-local readiness predicate over current contextual metadata:

```text
URI parses as /project-assets/{assetId}
+ session is authenticated
+ snapshot/current project IDs match
+ current project is in latest ownedProjects
+ matching metadata belongs to that project
+ kind=texture, storageKind=r2, importState=ready
+ mime/size/SHA are present
```

`BinaryTextureStore.has(uri)` is not durability evidence. Pass this predicate
to `computeCloudSaveBlocker` in both snapshot capture and final submission.
The final check uses the snapshot project ID so a stale draft or project switch
cannot borrow another project's ready row.

### D6 — Failure and retry matrix

| Failure point | Document/history | Retry |
| --- | --- | --- |
| Missing/invalid source bytes | unchanged; blocker remains | re-import/reselect bytes; no API call |
| Register fails | unchanged; no history | fresh action may register later |
| Upload fails before `ready` | unchanged; no history | retain bytes + same asset ID; retry PUT |
| Upload becomes `ready`, replacement is blocked/stale/fails | source URI unchanged; no history; ready row remains | retain completion intent; retry replacement without upload |
| Replacement succeeds, registry refresh fails | logical URI dirty; one history entry | upload response remains ready evidence; refresh separately |
| Replacement succeeds, P19 Save fails | logical URI stays dirty | retry ordinary Save; never re-upload |
| Undo after conversion | source URI restored; blocker restored | redo conversion or Save to project again; existing ready row is not deleted |
| Project switch/sign-out/unmount | stale completion discarded | in-memory retry cleared; durable ready row remains listed later |

Only an upload that has not reached `ready` retries PUT. A ready upload never
creates a second row merely because Scene mutation or project Save failed.

### D7 — Package export gets a narrow resolver fallback

Keep `buildPackage` unchanged. Extend `EditorStore.exportPackage` to accept an
optional async byte resolver and evaluate:

```text
BinaryTextureStore hit
→ return cached bytes

logical current-project URI miss
→ injected EditorApp resolver
→ metadata readiness/ownership check
→ authorized content GET
→ MIME + size + SHA verification
→ prime cache
→ return bytes

anything else
→ unresolved-binary rejection
```

Pass the callback through `EditorAppBar` to `EditorProjectMenu`; do not move
download DOM work or API ownership into `EditorStore`. A fetch or integrity
failure fails the whole export closed with the existing clear rejection path.

Plain JSON copy/download continues to block project-asset URIs. Package import
continues to restore package-local URIs and bytes and never auto-converts.

2. `apps/editor/src/lib/editor/editor-store.svelte.ts` — narrow replacement delegate, readiness-aware package resolver option; keep both existing blockers separate.
3. `apps/editor/src/lib/editor/app/EditorApp.svelte` — conversion/retry orchestration, ready-metadata upsert/predicate, final Save checks, authenticated package byte resolver.
4. `apps/editor/src/lib/editor/app/EditorSidebar.svelte` + `EditorAssetLibrary.svelte` — one conversion prop/action on eligible texture cards.
5. `apps/editor/src/lib/editor/app/EditorAppBar.svelte` + `EditorProjectMenu.svelte` — pass only the optional package resolver.
6. Tests where the behavior lands. No API, migration, schema, project-model, renderer, visitor, relic, layout, camera, selection, or placement implementation.

If the store host makes the mutator delegate mechanically awkward, the
replacement may live directly on `EditorStore`; do not create a controller for
one command.

## 5. Mount/unmount, history, and project semantics

- Guest, unauthenticated, unconfigured, unsaved, or foreign project: no
  conversion action and no private byte resolution. Existing local/package
  authoring and package export remain available.
- A guest with local bytes must export a package before OAuth, then authenticate,
  establish an owned project, re-import, and explicitly convert. No browser
  binary handoff is added.
- Project switch, explicit Load, sign-out, and unmount abort conversion/export
  fetches, clear retry/readiness state, and prevent late document/cache writes.
- Remote register/upload/fetch creates no editor history. Only URI replacement
  creates one Scene entry.
- Conversion preserves current selection, recent texture identity, material
  assignments, and texture ID because those key on the scene-local ID.
- Undo/redo never deletes, retries, or mutates registry/R2 state.
- `/museum/editor` receives no conversion/API props. `/museum` receives no
  imports, auth, private fetches, or logical-project resolver.

## 8. Boundaries and fallback

- No schema/version change: durable texture identity remains the logical URI.
- No R2 key, API URL, registry status, bytes, or retry state enters
  `ProjectDocument`.
- Do not relax `projectExportBlocker`; plain export and cloud durability remain
  different predicates.
- No second upload, history, selection, material, texture-cache, or renderer
  system.
- P20.4 owns automatic Load-time resolution and deployed end-to-end fidelity.

If URI replacement cannot preserve undoable source rendering without broader
history/cache work, ship conversion with retained session aliases as specified;
do not make conversion non-undoable. If authenticated package fallback expands
beyond the existing `ProjectApi` content GET, keep cache-backed package export
and defer only cache-miss export to P20.4. The cloud-Save durability gate must
not be weakened in either fallback.
