## Goal

Close the two remaining frozen-Chopin assumptions the S8.1 audit surfaced in
the shared editor path: **room focus is Paris-gated end-to-end**, and
**cluster grouping expands the wrong room**. Both are "works by luck for
Chopin, breaks for a greenfield room" rules left over from the relic.

- `focusRoom(id)` refuses every id except `'paris'`, and the camera rig frames
  a focused room through `getRoom(store.selectedRoomId)` — a Chopin `roomById`
  lookup that **throws** for any drafted id.
- `groupSelection` expands `'paris'` after grouping, even though a cluster can
  live in any room.

This slice makes both paths resolve the live room and keeps `/museum/editor`
observably unchanged. The H1 room frame deliberately switches to an
axis-aligned AABB frame (see "Frame from compiled bounds") — the one visible
camera change, accepted because the old yaw-following frame is unreachable in
H1 (it throws) and the AABB frame is what placement/selection already use.

## Locked decisions

### Room focus resolves the live room

- `focusRoom(id)` keeps its mutation/interaction guards but replaces the bare
  `id !== 'paris'` check with
  `(this.isRelic && id !== 'paris') || !this.rooms.has(id)` — relic mode stays
  literally Paris-only (a Chopin room like `entrance` still returns `false`),
  H1 accepts any live room. On success it stores the id in the camera-focus
  intent (add a `cameraFocusRoomId` beside `cameraFocusPlacementId` /
  `cameraFocusNodeId`) instead of relying on the selected room re-read through
  Chopin `getRoom`.
- The rig frames by `cameraFocusRoomId`, never by `selectedRoomId`.

### Frame from compiled bounds, not the Chopin MuseumRoom

- Add a pure renderer-neutral helper that converts a compiled room's
  `bounds3` into a world AABB, and have `EditorCameraRig` frame the `room`
  focus kind through the existing `createEditorBoundsCameraFrame` (the same
  path placements/selection use). No `getRoom` / `$lib/content/rooms` /
  `MuseumRoom` in the H1 branch.
- This is a deliberate frame-math change, not a semantic-preserving swap: the
  Chopin `createEditorRoomCameraFrame` uses a yaw-rotated offset + a
  `MuseumRoom.dimensions` radius, while the AABB frame is axis-aligned. For a
  yawed room the resulting camera differs; that is accepted because the old
  path is unreachable in H1 (it throws on a drafted id) and the AABB path is
  the one placement/selection already use.
- Missing-bounds fallback: `compileLayoutGeometry` skips rooms with blocking
  geometry issues (`hasBlockingLayoutIssues` → `continue`, no `bounds3`
  entry). A focused room with no compiled entry yields a `null` frame — a
  no-op, the existing `createEditorBoundsCameraFrame` empty-bounds behavior.
  (No registry AABB guess: a blocking-geometry room should not be framed.)
- The relic stays on `createEditorRoomCameraFrame(getRoom('paris'))`; gate the
  branch on `isRelic`. H13DView threads the per-room compiled bounds (or the
  `layoutPreview.geometry` lookup) into `EditorCameraRig` as an optional prop
  the relic does not pass.

### Cluster grouping expands the cluster's room

- `groupSelection` (shortcuts + inspector) calls
  `ensureRoomTreeExpanded(store.selectedCluster.roomId)` after a successful
  `createCluster()` instead of `ensureRoomTreeExpanded('paris')`.

## Implementation steps

### 0. Turn the contracts into failing tests first

Add to `tests/lib/editor/h1/placement.test.ts` (or a sibling `room-focus.test.ts`):

- `focusRoom(draftedRoomId)` returns `true` for a live (non-`paris`) room and
  stores `cameraFocusRoomId`; returns `false` for an unknown room and while
  mutation-blocked/interaction-active.
- Room framing: a focused drafted room resolves its compiled `bounds3` and
  produces a finite camera frame without throwing (the Chopin `getRoom` path is
  not reachable in H1).
- `groupSelection` in a non-Paris room expands that room's id, not `'paris'`.
- Relic: `focusRoom('paris')` + `getRoom('paris')` framing unchanged;
  `focusRoom('entrance')` (another Chopin room) still returns `false` in relic
  mode (the widened-gate regression pin).

- `session-state.svelte.ts` + `museum-editor.svelte.ts`: add `cameraFocusRoomId`
  and thread it through `setCameraFocus` (or an equivalent room-focus setter).

### 2. Room-agnostic `focusRoom`

- `museum-editor.svelte.ts`: replace the bare `id !== 'paris'` gate with
  `(this.isRelic && id !== 'paris') || !this.rooms.has(id)`; store the id.

### 3. Compiled-bounds framing

- Add the `bounds3` → world-AABB conversion (editor-side pure helper).
- `EditorCameraRig.svelte`: frame the `room` focus kind via
  `createEditorBoundsCameraFrame` when `!store.isRelic`; keep the Chopin path

### 4. Cluster expansion

- Manual: draft two rooms → focus each from the hierarchy (camera frames the
  room, no throw); group scene entities in a non-Paris room → that room expands;
  `/museum/editor` room focus still frames Paris; `/museum` visitor unchanged.
