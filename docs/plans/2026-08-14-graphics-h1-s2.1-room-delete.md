## Goal

Close the one missing Plan CAD mutation: **delete a room**. Today a user can
create, vertex-edit, resize, and relocate (B3) rooms — but never remove one,
which is exposed by S2's boot-blank flow (a misdrawn room on an empty project
is permanent unless the whole layout is reset). This sub-slice adds a guarded,
atomic room delete with a locked **reject-when-referenced** policy that keeps
the layout/scene domain split and the one-entry-per-gesture history contract
intact.

This is a layout-domain gesture only. It never mutates `project.scene`, never
crosses history domains, and adds no 3D gizmo delete (that is S7 territory).

## Target

```text
Plan view — room selected
  → inspector "Delete room" (danger)  |  Delete / Backspace key
  → guarded layout transaction
       ├─ blocked?  status message with per-kind scene-reference blockers
       └─ delete    remove room (openings, segments, interior anchors)
                    + owned layout objects
                    + portal refs (connectsRoomIds) in other rooms
                    → one `layout` history entry, selection cleared
```

- Deleting a room always cleans up its layout-internal content and any portal
  references other rooms' doors hold to it.
- Deleting is **blocked** while any scene content references the room; the
  block is descriptive (counts per kind), fail-closed, and writes no history.
- `project.scene` is never touched by this slice. Undo/redo stays single-domain.

## Locked decisions

### Policy: reject-when-scene-referenced, cascade layout-internal

- A room delete removes, atomically: the room from its floor (with its
  openings, boundary segments, and interior anchors), all layout objects owned
  by the room (`object.roomId === roomId`), and the `connectsRoomIds` portal
  relation on any *other* room's door that references the deleted room.
- The delete is **rejected** if `project.scene` references the room in any of:
  entities, clusters, navigation nodes, connection path anchors, target
  waypoints, or view-track keyframes. The failure message enumerates blockers
  by kind (e.g. "3 entities · 1 camera node") so the user knows why and can
  move/delete that content first.
- Rationale: cascade into the scene would require a multi-domain atomic gesture
  (two history entries or a compound entry), which violates the locked
  "one entry per gesture in the owning domain" contract. Cross-domain atomicity
  is explicitly deferred (C1 Beta / Frontier+). Reject is the cheap, honest,
  contract-preserving rule, and matches the repo's fail-closed precedent
  (A2.3, G4). On boot-blank projects, rooms with no scene content delete
  immediately.

### The delete is a guarded B3 layout transaction

- Flow: `beginLayoutTransaction()` → `deleteLayoutRoom(layoutPreview, roomId)`
  → `commitLayoutTransaction(captureLayoutPreviewSnapshot(layoutPreview))`.
- Exactly one `layout` history entry on success; none when blocked or no-op.
  Undo restores the room and all removed content. Selection is cleared on
  success (`layoutInteraction.selection = { kind: 'none' }`).
- Guarded by the existing `isDocumentMutationBlocked` /
  `isEditorInteractionActive` / transaction-live rules like every other layout
  mutation; Escape/cancel restores the pre-gesture snapshot via
  `cancelLayoutTransaction()`.

### Pure layer stays scene-free

- `deleteLayoutRoom(document, roomId): LayoutDocument | null` lives in a new
  editor-side pure module `layout-room-editing.ts` (sibling of
  `layout-opening-editing.ts` / `layout-object-editing.ts`); it knows nothing
  about `project.scene`.
- The scene-reference check is a separate pure function,
  `listLayoutRoomSceneReferences(scene, roomId)` → per-kind counts, placed in
  the editor layer that already owns `LayoutPreviewState.project` (scene-aware).
  `$lib/layout/**` stays Three/DOM/Svelte-free and scene-free (locked rule).

### Affordances

- **Inspector**: "Delete room" danger button in the room section (mirror the
  existing `layout-danger` "Delete object" button). Disabled with an
  explanatory title when blockers exist or during mutation locks.
- **Plan viewport**: Delete / Backspace deletes the selected room (only
  `{ kind: 'room' }` selection, layout workspace only). Extend the shortcut
  cascade with a layout-owned branch (`editorOwnsLayoutShortcuts` when
  `store.currentWorkspace === 'layout'` and focus is in the viewport); the
  scene/camera branches keep their current gating unchanged.
- No confirm dialog: the reject policy means a successful delete is fully
  undoable, consistent with Delete object/opening.

## Implementation steps

### 0. Turn the contracts into failing tests first

In `tests/lib/editor/h1/room-delete.test.ts` (new) + additions to
`tests/lib/editor/layout/layout-preview-state.test.ts`:

- Pure `deleteLayoutRoom`: removes the room, its openings/segments/anchors, and
  owned objects; clears `connectsRoomIds` on other rooms' doors; returns `null`
  for an unknown room; leaves `profile` objects in other rooms untouched.
- Preview-state delete: allowed case (internal cleanup only); blocked case for
  **each** scene reference kind (entity, cluster, navigation node, connection
  anchor, target waypoint, view keyframe); unknown room; deleting the last room
  yields a codec-valid empty layout.
- Transaction: one `layout` history entry on success, none when blocked; undo
  restores the room + content; selection cleared; `validateLayoutDocument` +
  `validateMuseumProject` pass post-delete.

### 1. Pure room deletion

- Add `layout-room-editing.ts`: `deleteLayoutRoom(document, roomId)` — clone,
  remove room from its floor, filter owned objects, map other rooms' openings
  to drop `connectsRoomIds` relations that mention `roomId`, return the next
  document (or `null` for unknown room). No scene imports.

### 2. Preview-state mutation + blocker

- Add `deleteLayoutRoom(state, roomId): LayoutRoomEditResult` to
  `layout-preview-state.svelte.ts`: enumerate scene blockers via
  `listLayoutRoomSceneReferences(state.project.scene, roomId)`; if any, fail
  with the per-kind message and set `lastMutationMessage`; otherwise clone,
  `deleteLayoutRoom`, and ride the existing `applyLayoutMutation` gate
  (strict codec + geometry + bundle rebuild).
- Add the scene-reference enumerator in the same editor layer: counts per kind
  from `scene.entities`, `scene.clusters`, `scene.navigationNodes`,
  `scene.connections[].positionPath.anchors`,
  `scene.connections[].targetWaypoints`, and
  `scene.connections[].viewTracks.*`.

### 3. Inspector

- Room section of `EditorInspector.svelte`: "Delete room" `layout-danger`
  button next to the existing room fields; disabled while
  `isDocumentMutationBlocked || isEditorInteractionActive || transaction-live`
  or when blockers exist (title shows the blocker summary); calls
  `store.beginLayoutTransaction()` → `deleteLayoutRoom(layoutPreview, id)` →
  `store.commitLayoutTransaction(...)` and clears the layout selection on
  success.

### 4. Shortcut branch

- `hooks/shortcuts.svelte.ts`: add a layout-owned Delete/Backspace branch
  (workspace `'layout'`, viewport focus, `layoutInteraction.selection.kind ===
  'room'`) delegating to the same guarded transaction helper. Keep the existing
  scene/camera branches byte-identical.

### 5. Regression + manual QA

- Full suite + `svelte-check` + production build.
- Manual: boot blank → draw two rooms + a door portal + a layout object →
  delete a room (portal refs cleared, object gone, one undo step restores);
  place a scene entity in a room → delete is blocked with the per-kind message;
  delete the last room → empty layout stays valid; undo/redo across
  interleaved scene edits stays single-domain; `/museum` + `/museum/editor`
  relics unchanged.

## Regression matrix

| Concern | Required assertion |
|---|---|
| Atomicity | Delete removes room + owned objects + portal refs in one gesture; one `layout` history entry; undo restores all |
| Reject policy | Delete blocked while any entity/cluster/nav-node/anchor/waypoint/keyframe references the room; no history entry; message lists kinds |
| Codec validity | Post-delete document passes strict `validateLayoutDocument` + geometry; deleting the last room yields a valid authoring-empty layout |
| Scene isolation | `project.scene` byte-identical after any room delete; project codec stays green |
| UI | Inspector danger button + Delete key both reach the same guarded transaction |
| Selection | Room selection cleared on success; blocked delete preserves selection and document |
| Relic isolation | `/museum` + `/museum/editor` unchanged; no `$lib/layout/**` scene imports |

## Non-goals (deferred)

- Wall / opening / anchor deletion by keyboard in Plan (openings already have
  inspector + viewport delete; wall delete is a separate product question).
- Cascade deletion of scene content (entities, camera nodes, connections) — a
  multi-domain atomic gesture, deferred with C1 Beta.
- 3D room deletion via the gizmo host (S7) and unified hierarchy (S4).
- Multi-select room deletion.
- Deleting a floor (deleting all its rooms) — keep the slice room-scoped.
