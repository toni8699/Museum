## 1. Buckets (P11 §8 + owner decisions 2026-08-26)

| Mark | Meaning | Rule |
|---|---|---|
| **AA** | always-allowed while playing | drop `isDocumentMutationBlocked` from the gate (keep `isEditorInteractionActive` / pending-nav / selectable checks) |
| **AP** | auto-pause-first | replace blocked-refusal with the seam: visitor → refuse; director playing → `pauseCameraPreview()` (session-only, preserves physical progress, no history entry) then proceed; interaction-active → still refuse |
| **SB** | stays-blocked | unchanged refusal while playing/visitor (non-Camera document edits — owner decision 1) |
| **CH** | chrome/session (⊂ AA, owner decision 2) | workspace/tab/sidebar/timeline-shell/tree-expansion session writes |
| **DEL** | ⊂ AP, owner decision 3 tail | topology deletion: pause-then-proceed into existing `#releasePausedPreviewForTopology` force-stop |

Owner decisions recorded 2026-08-26: (1) non-Camera document edits **stay
blocked** while playing; (2) shell/session chrome **always allowed**
(supersedes today's `setWorkspace`/chrome blocks per §8 "workspace/domain-view
navigation"); (3) topology connect/order/timing **auto-pause first**;
deletion keeps its force-stop. Shortcut swallowing (`shortcuts.svelte.ts`)
and transform-tool keys remain **deferred** (P11 §14 — shortcut audit).

Seam contract: `requestAuthoringPause(): boolean` on the facade — false for
visitor; pauses a playing Director preview via the existing
`cameraPreviewCommands.pauseCameraPreview()` (run-id/captured-route rules
untouched) and returns whether authoring may proceed. Pure session transition;
never opens/closes a history transaction; never calls `stopCameraPreview()`.

Implementation refinement (2026-08-26): the framing gates (P1.6
`isCameraFramingMutationBlocked` rows) use a `requestFramingPause()` variant —
paused previews of EITHER mode pass through (pinned paused-Through-Camera
contract: `editor-store-camera.test.ts` :3026/:3056), a *playing* preview goes
through the document seam (visitor playing still refuses). The plain seam stays
visitor-refusing for document writes. DEL note: a paused Director SEQUENCE is
hard-reset by P8 S5's `refreshPausedDirector` on any document swap, so sequence
deletions always end force-stopped; the untouching-keep case is an EDGE-preview
behavior (`#releasePausedPreviewForTopology`).

Canonical guard order (pinned 2026-08-26, audit of all 38 seam call sites):
**prohibited-state checks (`isEditorInteractionActive` /
`isDocumentTransactionActive` / `pendingNavigationCommand`) → validate/resolve
the target → `requestAuthoringPause()`/`requestFramingPause()` →
`beginDocumentTransaction()`/`beginCameraFramingTransaction()` → write /
pointer-capture.** Rules: (a) a *rejected* gesture (interaction/transaction /
pending-nav bars, missing or stale target, invalid input, unchanged value)
never pauses — the seam fires only once the write can actually proceed;
(b) unchanged/invalid commits never open a transaction (the old open-then-
cancel-on-noop churn is gone); (c) the seam never runs under an open
transaction and never writes history. Commits/blurs validate first; genuine
drag *begins* resolve their target identity first, then pause, then begin.

## 4. Prohibited floor (unchanged everywhere)

Visitor previews refuse all of the above (seam returns false). Undo/redo while
playing stays blocked (`isDocumentUndoBlocked` untouched). Active
drag/transaction/pending-navigation bars stay. One gesture = one transaction
preserved: the pause happens before pointer capture / `beginDocumentTransaction()`,
and pausing itself writes no history entry. `stopCameraPreview()` teardown
semantics unchanged (Escape, stale cleanup, document replacement, domain exit).
