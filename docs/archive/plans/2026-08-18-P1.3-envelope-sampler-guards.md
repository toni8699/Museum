## Outcome

Connections with authored view keys and a directional `framingEnvelope` blend
automatic travel-facing framing with authored framing in `sampleCameraMotion`:

```text
w(p)      = enterRamp(p) × exitRamp(p)
target(p) = lerp(autoTarget(p), authoredTarget(p), w(p))
fov(p)    = lerp(autoFov(p), authoredFov(p), w(p))
```

Ramps use one canonical `smootherstep` helper. Sampling remains deterministic
and seekable: same motion + progress always gives same pose, regardless of prior
samples. POI pass-through, collinear-zero, and late-exit double-whip cases get
geometry-driven guards without replacing Cartesian point blending.

Existing behavior stays exact when envelope is absent. Tracks without authored
keys stay automatic even if malformed programmatic input carries an envelope.
Reversed edges without reverse keys keep `travelFacingEnds` behavior.

Out of scope:

- envelope creation, auto-managed/manual policy, handles, presets, warnings;
- endpoint overrides, custom weight curves, direct rotation-speed controls;
- P1.4's exhaustive continuity/FOV-pacing matrix;
- shell, Camera Plan, selection, persistence, `/museum/editor`, or scene schema;
- changing node poses, path geometry, easing semantics, or motion duration.

## Existing seams to reuse

- `camera-route.ts` remains sole route builder. `buildOrientedViewTrack` already
  selects one direction's envelope; `buildLookAheadTargets` owns automatic
  target generation and `travelFacingEnds`.
- `camera-motion.ts` remains sole motion engine. `createMotionEdgeView` already
  owns prepared automatic/authored layers; `sampleAuthoredView` already samples
  node → keys → node using interval easing; `getEdgeLocalProgress` already maps
  global eased travel to distance-based edge progress.
- `VISITOR_CAMERA_PROJECTION.near` is minimum target standoff. Do not duplicate
  `0.1` in guard code.
- `CameraDirector`, editor preview, timeline, and keyframe controller already
  call `sampleCameraMotion`; no consumer-specific sampling path or prop change.

## Sampling contract

Add focused pure helpers in `camera-motion.ts`:

1. `smootherstepRamp(progress, start, end, rising)`:
   - rising ramp is `0` before `start`, `1` after `end`;
   - falling ramp is `1` before `start`, `0` after `end`;
   - equal bounds are deterministic steps: rising switches at the bound,
     falling switches after the bound; endpoints remain finite.
2. `sampleFramingEnvelopeWeight(envelope, p)` returns rising enter × falling
   exit, clamped to `[0, 1]`. Keep internal unless tests need a public seam.
3. Split current authored branch into automatic and authored samples, then
   blend once. Keep hot-path allocation-free: store scalar automatic target
   components/FOV before authored sampling, then write blended values into the
   caller-owned `CameraMotionSample`.

Branch matrix:

- legacy route / missing edge view → current legacy target path + FOV path;
- edge view, no authored keys → current automatic target + node-FOV lerp;
- authored keys, no envelope → current authored target/FOV exactly (`w = 1`);
- authored keys + envelope → blended target/FOV, then target-only guards.

Apply envelope to edge-local distance progress, not raw playhead progress.
Apply motion easing once globally and existing interval easing once inside the
authored track; envelope ramps consume resulting local distance progress and do
not reapply `motion.easing`.

## Guard architecture

Guards must work during visitor playback, paused editor preview, reverse seeks,
timeline scrubbing, and random-access tests. Therefore no previous-frame state,
module scratch vectors, or consumer-owned correction state.

During `createCameraMotion`, compile optional immutable guard metadata for each
authored/enveloped edge from existing position path, automatic target path,
authored track, envelope, FOV, edge duration, and endpoint pose. Runtime
`sampleCameraMotion` evaluates raw Cartesian blend first, then applies only the
compiled correction. Normal edges keep `guard: null` and exact direct sampling.

Use one named `CAMERA_FRAMING_GUARD_POLICY` for numeric safety/comfort limits.
Every value needs unit-bearing name and boundary test. Geometry/projection
values derive from existing policies where possible; no anonymous angle,
progress, sample-count, or distance literals inside branches.

### 1. Collinear-zero and standoff

- Detect raw blended target distance to sampled eye.
- If distance is at least `VISITOR_CAMERA_PROJECTION.near`, preserve raw point.
- Inside standoff sphere, project target to sphere along compiled continuous
  gaze direction. Prefer normalized raw direction; at zero/near-zero use guard
  direction continued from neighboring safe samples, never arbitrary world axis.
- Preserve target distance outside danger zone. Guard changes target only, not
  eye, FOV, weight, authored keys, or endpoints.
- Blend correction on/off with derivative-continuous smootherstep shoulder so
  sphere entry cannot create new angular pop.

This is post-processing around singular set only. Core Cartesian
`lerp(autoTarget, authoredTarget, w)` remains authoritative.

### 2. POI spin-around angular clamp

- Compile gaze directions over envelope-active interval using adaptive samples;
  subdivide where angular delta or target-distance curvature exceeds policy.
- Unwrap directions by shortest-arc continuity. Where raw angular velocity
  exceeds named radians/second policy, apply forward/backward derivative-
  continuous limiting while pinning safe interval boundaries and node endpoints.
- Reconstruct corrected world-space target using raw focus distance, subject to
  minimum standoff. Thus clamp controls orientation without flattening intended
  parallax/focus-distance changes.
- Runtime seeks interpolate compiled correction by edge-local progress. Result
  cannot depend on sampling order or frame rate.

### 3. Late-exit double-whip bypass

Evaluate only when `exitEnd < 1`. Detect from geometry/time, not a magic
`exitStart > n` test:

- compare raw exit gaze path with shortest continuous route from authored gaze
  at exit onset to Node B gaze;
- require an off-axis detour/reversal beyond policy tolerance; and
- require remaining edge time to violate angular-rate policy if raw auto-facing
  detour is retained.

When both conditions hold, compile one smootherstep bypass from sampled authored
target at bypass start directly to canonical Node B target. Preserve world-space
Cartesian target interpolation and minimum standoff. Pin Node B exactly at
`p = 1`. FOV continues normal envelope blend; P1.4 owns FOV-pacing criteria.

Thresholds live in `CAMERA_FRAMING_GUARD_POLICY` and tests pin both sides of each
decision. Fixtures must show a late aligned endpoint does not bypass, an early
off-axis exit with enough time does not bypass, and a late off-axis hazardous
exit does bypass.

   all-equal bounds, finite `[0,1]` result, exact endpoint values.

   Cartesian lerps at distance-based local progress.

   stays automatic; reversed-with-keys uses its envelope; reversed-no-key stays

5. Standoff/collinear-zero: exact straddle and epsilon-offset fixtures return

   enough-time controls retain raw blend; endpoint remains exact.
8. Allocation/ownership: route/envelope inputs remain unmutated; repeated samples
   reuse caller vectors; separately created motions share no mutable guard state.
9. Golden route: legacy fixture samples at representative progress values match
   checked-in pre-P1.3 position/target/FOV numbers exactly.

## Completion

External review (2026-08-19) found two guard defects that blocked shipping;
both are repaired in `camera-motion.ts` with regression tests:

1. **Antipodal direction interpolation.** Both `sphericalDirectionLerp` and the
   runtime mirror `sampleCompiledGuardDirection` routed near-antipodal gaze
   directions through normalized linear interpolation, whose midpoint is the
   zero vector — producing a stall-then-180° flip and, at the mirror site, an
   eye-coincident target (`target === position`). Both now use a deterministic
   orthogonal great-circle path through a fixed reference; the well-conditioned
   linear path remains for near-parallel directions.
2. **Over-capacity full-edge remap.** The angular-rate fallback (and the
   per-step limiter) remapped gaze across the whole edge, rewriting automatic
   framing where envelope weight is zero. Correction is now scoped to the
   envelope-active interval with raw directions pinned at the boundaries, and
   the capacity/angle budget is measured over that interval only.

Regressions: `interpolates antipodal guard directions along a deterministic
great circle` and `restricts over-capacity correction to the envelope-active
interval` in `camera-motion.test.ts`; both fail on the pre-fix code. Full
suite 1,716 green (1 skipped); `svelte-check` 0 errors / 0 warnings.
