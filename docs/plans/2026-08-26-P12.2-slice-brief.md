## 2. Design decisions

- **D1 — Selection is selection-only (Laws 2–4); `installSelectionScope` is retired.** `selection-actions` stops calling it; then deprecate/delete the commands method + facade delegate. Explicit `previewEdge` / `previewCamera` (playhead 0, paused) are the scope-entry commands. Do **not** repurpose `installSelectionScope` — its Sequence-progress handoff is P11 semantics, not P12.
- **D2 — Sequenced-node click in Sequence scope: pure Sequence seek + pause.** New non-selecting primitive (one authority for all Sequence-scope seeks):

  ```ts
  // camera-timeline-controller
  seekSequencePreview(progress: number): boolean
  // validate Sequence scope + resolved progress/boundary
  // → requestTransportPause()
  // → setCameraPreviewPlayhead(progress, sequenceRunId)  // syncs cameraTimelinePlayhead (pinned: editor-store-camera.test.ts:1999-2000)
  // → NO selection mutation, NO Camera/Edge install
  ```

  `selectNavigationNode(C)`: commit canonical selection → if active scope `sequence` && C sequenced && evaluable boundary → `seekSequencePreview(boundary.progress)`. **Boundary disambiguation:** generic viewport/tree clicks use the deterministic nearest boundary to the current playhead (matching `stepCameraTimeline` cue selection); only an explicit timeline-dot click with a `boundaryIndex` targets the exact occurrence (loop nodes can appear twice via the closing edge). Post-gap/malformed → `lastEvaluableBoundary` (D7) + existing `Gap at Node N` diagnostic. Outside Sequence scope → selection only.
- **D3 — Preview Camera is Unsequenced-only.** `commands.previewCamera` and every entry point reject sequenced nodes (`guidedTourNodeIds` membership). Sequenced node context menus hide/disable `Preview Camera` with a tooltip pointing to Sequence-scope static inspection. Supersedes the P11.1 "Preview Camera works for every camera" grammar (§3).
- **D4 — `requestTransportPause()` + strict order.** New seam, modeled on `requestAuthoringPause` minus the visitor refusal: `if (cameraPreview && transport !== 'paused') pauseCameraPreview(); return true;` — pauses POV or Observer. **Pinned order on every seek path:** prohibited-state guard → validate input / resolve timeline / resolve boundary → `requestTransportPause()` → write playhead. An invalid scrub, stale node, missing timeline, or no-op target must not pause playback as a side effect. `requestAuthoringPause`/`requestFramingPause` remain the document/framing-write gates (§4 seam split).
- **D5 — Sequence scrub uses the same primitive; no pose-helper reuse.** `seekCameraTimeline` in Sequence scope: resolve global progress → `requestTransportPause` → `setCameraPreviewPlayhead(progress, sequenceRunId)` → preserve canonical selection → preserve Sequence scope. **No `selectCameraConnectionDirection`, no `showCameraTimelineConnectionPose`** (both install scopes). One primitive serves ruler scrub, sequenced-node seek, and step.
- **D6 — Direction choices: reuse, don't build.** Acceptance-pin `getCameraEdgePreviewChoices` (Sequence-adjacent single predecessor→successor; non-adjacent both directions; never storage-order fallback) and re-audit `EditorCameraEdgePreviewActions` mounts per §3. No new chooser component in S2; S3 mounts the same choices inside the Scope pill.
- **D7 — Evaluable-prefix resolution (new derived data, in the canonical layer).** §4's "seeks to last evaluable boundary" has no data source today (`{ timeline, diagnostic }` returns `timeline: null` on gap). Add to `editor-camera-timeline.ts` (not selection-actions/UI):

  ```ts
  type SequenceTimelineResolution =
    | { timeline: EditorCameraTimeline; diagnostic: null }
    | {
        timeline: EditorCameraTimeline | null;
        diagnostic: CameraRouteError;                     // gap / no-flow
        lastEvaluableBoundary: EditorCameraTimelineNodeBoundary | null;
      };
  ```

  `lastEvaluableBoundary` derives from the evaluable prefix of the route before the gap. The existing `{ timeline, diagnostic }` boundary shape stays, widened with the derived boundary. S2 must not rebuild route semantics outside `editor-camera-timeline.ts`.
- **D8 — Scrub/step availability (§4 mode-independence).** `scrubDisabled` / `edgeScrubDisabled` / step guards: **do not disable merely because `transport === 'playing'` or POV/visitor** — a playing scrub now pauses first via the seam. Keep disabling for active interaction/transaction, missing timeline, zero duration, and invalid targets. Edge scrub moves behind a command: `seekEdgePreview(progress)` → `requestTransportPause` → `setCameraPreviewPlayhead(progress, runId)`; the Ruler stops writing the playhead directly.

## 5. Test matrix

- sequenced node click, Sequence scope → seeks boundary, `paused`, playhead at boundary, **no scope change**;
- sequenced node click, Edge/Camera scope → selection only; scope/playhead/transport unchanged;
- post-gap node click → seeks `lastEvaluableBoundary` + `Gap at Node N` (typed boundary, no string parsing);
- loop node (closing edge) → nearest-boundary rule on generic click; exact occurrence on `boundaryIndex` click;
- edge click, all scopes → selection only;
- unsequenced node click → selection only; explicit Preview Camera installs Camera scope;
- sequenced node → Preview Camera unavailable; static inspection via `Sequence → boundary → paused`;
- `requestTransportPause()`: seek/scrub/step pause a playing preview in **POV and Observer** (mode-independent; supersedes P11.2 refusal pins);
- scrub/step **enabled while playing** (pause-then-seek); still disabled for interaction/transaction/zero-duration/missing timeline;
- invalid scrub (non-finite, stale node, missing timeline, no-op target) does **not** pause (D4 order pin);
- Sequence scrub leaves scope and selection unchanged (Law 2 pin);
- Sequence-adjacent Preview Edge → single predecessor→successor action; non-adjacent → explicit two-direction choice, never storage-order fallback;
- `installSelectionScope` retired — no callers remain (source assertion);
- migration: `p11-s1` selection-install assertions → selection-only assertions; `p8-s2` D1-family pins reconciled per §9.

## 7. Risks

- **Seek-scope reversal is the largest semantic change** (P11.1 shipped scrub-into-edge-scope). Isolate behind the §4 matrix tests; land D5 (scrub) separately from D2 (node click).
- **Recursion trap:** never call `selectCameraTimelineNode` from `selectNavigationNode` (it re-enters selection + installs Camera). The pure `seekSequencePreview` is the only path.
- **Pose helpers install scopes** — `showCameraTimelineNodePose`/`showCameraTimelineConnectionPose` must not appear in any S2 seek path.
- **Evaluable prefix is new derived data** — keep it in `editor-camera-timeline.ts`; do not compute "last evaluable boundary" in selection-actions or UI.
- **Scrub-while-playing is a contract requirement, not an affordance** — removing the disable must land with the pause seam (D8), or scrub-while-playing seeks without pausing.
- `installSelectionScope` callers are exactly the two `selection-actions` sites + the facade delegate — grep before removal.
