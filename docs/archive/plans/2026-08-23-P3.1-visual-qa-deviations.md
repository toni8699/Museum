## Audit summary

The shipped shell is structurally conformant (domain×view matrix, workspace
ownership, capability routing, sidebar model, timeline frame, status bar all
match the locked-shell registry) but is still on the interim S10.1.7
**warm-gold** visual system. Every finding below resolves into exactly three
fix buckets: **P3.2** (token/typography/icon architecture), **P3.3**
(visual defect pass), or **recorded deviation** (not fixable inside P3's
visual-only boundary).

## Semantic conflicts recorded (source precedence applied)

These v1-table rows from the P3 umbrella conflict with current source reality;
per the P10-era rebase rule they are **translated forward, not implemented as
written**:

1. **Camera-node "Rename" menu item (v1 table):** no name field exists on
   navigation nodes and no rename mutator exists anywhere in `src/lib/editor`
   (verified by grep). Item dropped from P3.5 scope rather than inventing a
   name model. Same disposition as scene-model Rename in the deferred list.
2. **Scene Plan "Staging" wording:** the live surface is the owner-aware
   **Arrange** mode (`PlanViewMode` value `'staging'` retained as the
   identifier; UI copy already says Arrange). P3.4 routes through
   `resolveArrangeHit` per the 2026-08-23 rebase.
3. **Camera Plan "Connect" menu item:** connect is an armed two-click tool
   through the interaction FSM (`beginConnectExistingNodes()` takes no target);
   there is no single-command "connect from here" facade command. Item deferred
   rather than building a new command (same rule as Edit Path).
