# P17 — editor / visitor app split

**Status:** shipped 2026-08-30. **Date:** 2026-08-30. **Depends on:** P16.
**Source:** backend/persistence migration review, Slice 3 / App-split pass.

## Outcome

Ship two deployable SvelteKit apps: `@portfolio/editor` owns `/`, `/editor`,
development tools, and the gated `/museum/editor` relic; `@portfolio/museum`
owns only the read-only `/museum` visitor. Both consume the canonical
`camera-core`, `project-model`, and `layout-core` packages.

Out of scope: backend/API provisioning, persistence, deployment manifests,
auth, visitor redesign, editor behavior changes, and a fork of the relic.

## Existing APIs and ownership

- Reuse the current route components and SvelteKit configuration.
- Keep project, scene, layout, codec, graph, and camera execution in the three
  existing `@portfolio/*` packages.
- Keep editor session, selection, history, hover, gizmos, import/export, and
  shell code inside `apps/editor`.
- Keep the checked-in Chopin document and visitor runtime inside
  `apps/museum`; generated endpoints remain derived only.

## Change surface

- Rename the current app/package to `apps/editor` / `@portfolio/editor`.
- Create `apps/museum` from the existing visitor-only source surface and
  static production assets; do not add an editor dependency or source alias.
- Move `/museum` ownership to the visitor app. Preserve `/museum/editor` in
  the editor app through the existing virtual relic entry.
- Point root dev/test at the editor and root build/check at both apps.
- Update the lockfile, live boundary docs, and source/runtime boundary pins.

No new runtime dependencies, props, state, selection semantics, or document
mutations are introduced. Mount/unmount behavior stays route-owned exactly as
before.

## Acceptance

1. `apps/museum` contains no `editor` source directory and no editor imports.
2. Its built `/museum` server/client closure contains no editor entry.
3. `apps/editor` serves `/`, `/editor`, and `/museum/editor`, but not `/museum`.
4. `npm test` passes the existing suite, including the source-boundary pin now
   rooted at the standalone visitor app.
5. `npm run check`, `npm run build`, and `npm run verify:visitor-bundle -w
   @portfolio/museum` pass.
6. `/museum` remains the checked-in Chopin visitor; editor and relic behavior
   are unchanged.

## Fallback

If deployment routing cannot mount the two outputs at their owned paths, keep
the apps split and add host-level routing in the deployment pass. Do not
recombine source trees or create a shared Svelte runtime package.
