# P1.7 — Camera UI reconciliation (light pass)

**Status:** shipped 2026-08-21
**Parent:** [P1 camera overhaul](../../plans/2026-08-18-P1-camera-overhaul.md) §A / §D
**Depends on:** P1.1 shell; P1.5 Camera Plan surface; P1.6 framing authoring
(including its manual GUI acceptance walk — P1.6 does not close until those
scenarios pass)
**Terminology amendment (2026-08-21, per P1.8 / `Camera-flow-specs.md` §2):**
the Camera sidebar section is named **Unsequenced**, not "Free Cameras"; all
references below use it, and the shell spec §4 + visual spec §10 are already
amended — P1.7 implements the sidebar with the new name.
**Unblocks:** P1.8 camera sequence authoring; P1 close (DoD item "P1.7
reconciliation done (interim presentation; the P3 pass is separate)"); P3 owns
the full visual overhaul

## Outcome

Camera domain's interim presentation is reconciled to the shell spec's Camera
surface without changing camera behavior or the shell architecture. The
Camera left panel becomes the canonical **four-section Camera Sidebar**
(Environment · Sequence Inspector · Unsequenced · Connections); the Camera
Plan/3D viewports carry explicit guided-order numbering and unsequenced-camera
distinction; the timeline's two lanes get tour-control and lane polish; the
domain-switch animation stops being instant; and the P1.5/P1.6 surfaces get a
**light** visual/spacing/label pass. This is explicitly **not** the P3
overhaul: no blue-token migration, no `styles/` directory, no
`Design-specs.md` visual conformance. After P1.7 the P1 definition of done is
met and the umbrella archives.

The heavy lifting for the sidebar already exists inside
`CameraFlowPanel.svelte` (guided chain, sequenced/unsequenced split, detour
groups, loop row, unused-connections tray, drag reorder through
`setGuidedTourOrder`, timing readouts) and `plan-camera-projection.ts` (order
labels + unsequenced badges).
P1.7 is composition, routing, assertion, and polish — not new camera
semantics.

## Scope (pinned)

### 1. Dedicated Camera Sidebar (shell spec §4 "Camera domain"; P1 §A.2 row 4)

Replace the Camera-domain left panel — today the `UnifiedProjectTree` with
read-only environment rows and the embedded **Camera Flow** root — with the
canonical four-section sidebar:

```text
Environment
Sequence Inspector
Unsequenced
Connections
```

- **Environment** — read-only context (museum / floor / rooms / architectural
  elements). Reuse the tree's existing read-only environment rows; Camera
  domain must not mutate it. Scene-only Hierarchy/Assets tabs and Add Room
  stay hidden (already true).
- **Sequence Inspector** — the guided tour in order: order number, camera
  name, drag reorder, selection, visibility, contextual actions, optional
  timing. Build from `store.guidedTourNodeIds`; reuse `CameraFlowPanel`'s
  chain rows, the loop row (`showLoopRow`/`flowLoopConnectionId`), detour
  groups, and drag reorder (`setGuidedTourOrder`, one history entry).
- **Unsequenced** — nodes not in `guidedTourChain` (`freeNodeIds`), may still
  participate in connections.
- **Connections** — undirected topology list rendered as `Camera A — Camera B`
  (never `→`); reuse the `unusedConnectionRows` tray plus chain records.

Routing: Camera domain shows the sidebar; Scene domain keeps the unified tree
unchanged. The relic mount (`MuseumEditorApp` via `EditorCameraTree`) keeps
today's behavior or is verified equivalent — behavior stays frozen.

### 2. Viewport guided/unsequenced + numbering (spec "Viewport MUST show")

Already shipped in P1.5 (`camera-order-label` + `camera-unsequenced-badge` in
`plan-camera-projection.ts`; badge renamed 2026-08-21 per P1.8). P1.7 work:
**verify and pin by test** — guided sequence numbering renders for ordered
nodes, unsequenced cameras render the "Unsequenced" badge, ordered/unsequenced
stay visually distinguishable, and connections render undirected (no arrows) in
both Plan and 3D. Fix only what the assertions find.

### 3. Timeline lane + tour-control reconciliation (P1 rows 10/12, spec §11)

- Keep the two semantic lanes — **Guided Route** and **Camera Framing**
  (the P1.6 band/handles lane) — no regression into raw Position/Target/FOV
  tracks; polish lane labels and visual hierarchy.
- Tour selector and timeline zoom "where practical" are the **unbuilt** items
  from spec §11 (verified absent in code today). P3's conformance boundary
  explicitly excludes "timeline detail not built by P1.6/P1.7" — so
  deferring past P1.7 drops them off the roadmap; P3 will not pick them up.
  Land the **tour selector** in P1.7: the Sequence Inspector sidebar already
  selects/orders the guided chain through the same store accessors, so the
  timeline control is a small reuse, not new machinery. **Zoom** stays only
  if it fits the light scope; otherwise record it as deferred-off-roadmap
  with a note (re-register later) — never build it interim now and again in
  final form later.
- Plan ↔ 3D continuity invariants (no timeline reset on switch) already hold
  (P1.1); P1.7 must not regress them. P1.6's handle-drag cancel on surface
  swap stays.

### 4. Domain-switch animation (spec §20, deferred polish)

Replace the instant domain switch with the spec's ~180–220 ms animation.
Non-behavioral; selection/state continuity unchanged.

### 5. Interim presentation polish (light — NOT P3)

Spacing, labels, empty states, alignment, and hover/focus affordances over
the P1.5 Camera Plan surface, the P1.6 framing controls (presets, diagnostics,
Advanced), and the envelope band/handles lane. No token/typography/icon
migration; no `styles/` directory; no `Design-specs.md` conformance — P3 owns
all of that.

## Out of scope

- P3 visual overhaul (tokens, typography, icons, `styles/`), P2 staging,
  P4/P5, and the P7 facade increments — all separate plans.
- Boot `Scene → Plan` change (deferred, non-architectural).
- Camera behavior/semantics: no new authoring features, no path/topology,
  motion sampler, schema, import/export, visitor, or relic changes.
- Asset-management state (spec §8) — deferred (not in P1).

   cameras appear ordered in Sequence Inspector, unsequenced cameras under
   Unsequenced, and connections listed undirected.

   Plan and 3D both reflect the new order numbers.

   (numbered vs badge), and that edges never render arrows.
4. Switch Plan ↔ 3D repeatedly: timeline keeps playhead, expanded state,

   (~180–220 ms) instead of snapping.
5. Open framing controls (presets/diagnostics/Advanced) and the envelope

## Boundaries and fallback split

- `/museum` and `/museum/editor` stay frozen; no editor code in `/museum`
  visitor chunks; editor ships in production (no build-flag gating).
- Scene truth remains `store.document` + `store.rooms`; no boot-time layout
  copy, no second graph/route/motion/timeline projection.
- No commits unless the owner asks.

Build as two serial green checkpoints if the diff grows:

1. Camera Sidebar composition + viewport numbering/unsequenced assertions +
   timeline lane/tour-control polish;
2. domain-switch animation + interim presentation polish + contract
   hardening.

Checkpoint 2 may be reverted without behavior rollback; checkpoint 1 still
leaves a complete, reconciled Camera surface. P1.7 does not close until both
checkpoints and all manual scenarios pass and the P1 umbrella's DoD is met.
