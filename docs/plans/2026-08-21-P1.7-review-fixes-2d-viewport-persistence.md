## Checkpoint 1 — Camera 3D guided numbering + Unsequenced badge (review Finding 1)

Shell spec §"Viewport MUST show" (Camera domain) requires guided sequence
numbering + unsequenced distinction; P1.7 acceptance says "both Plan and 3D";
manual scenario 3 expects "numbered vs badge" in Camera 3D. Today only the Plan
projection implements it (`plan-camera-projection.ts`). Camera 3D
(`EditorCameraHelpers.svelte`) renders bare position/target markers.

### Implementation

1. **Pure label model** — new `editor-camera-labels.ts` (or fold into existing
   editor-navigation-graph helpers): input `guidedTourNodeIds` + navigation
   nodes → per-node `{ order: number | null, unsequenced: boolean }`.
   Unit-test it (guided gets 1..N by chain index; non-chain nodes get
   `unsequenced`; detour nodes follow whatever the sidebar shows — match
   `freeNodeIds` semantics: not in `guidedTourChain` ⇒ unsequenced).
2. **DOM overlay in the 3D cell** — project each camera-node position marker to
   screen space per frame and render small labels (order digit / "Unsequenced"
   badge). Established precedent: `EditorOrientationGizmoOverlay` (DOM synced to
   3D). Prefer reusing its sync pattern over introducing sprites/@threlte/extras.
   - Hide labels whose node has no runtime helper (deleted/drafted-room trap:
     resolve through `store.rooms`, never `chopinRuntime.rooms`).
   - Interim styling only — no token migration (P3 owns visuals).
3. **No-arrow assertion (3D)** — pin that `EditorCameraPathHelpers` emits
   line/curve geometry only (no cone/arrow objects). Source-contract test
   (repo pattern) or geometry-type scan; whichever matches existing test style.

## Checkpoint 2 — 2D keeps viewport across Scene ⇄ Camera (parity with 3D)

Today `EditorApp.svelte` center cell swaps `PlanWorkspace` (Scene) ↔
`CameraPlanWorkspace` (Camera) via `{#if}/{:else if}` — full unmount/mount,
pan/zoom reset, cross-fade. 3D already keeps one mounted component. Make 2D
match: both surfaces stay mounted; only sidebar/menu functionality changes.

### Implementation

1. **Keep both mounted** — when `activeView === 'plan'`, render *both*
   `<PlanWorkspace>` and `<CameraPlanWorkspace>`; toggle visibility by domain.
   Precedent: sidebar tabs ("both panels stay mounted; inactive hidden by
   class") and G3 (both Camera cells mounted so timeline state persists).
   - Hidden mechanism: `workspace--hidden` class (`display: none`) + `inert`
     so the hidden surface never receives pointer/keyboard input.
2. **Transitions** — remove `transition:editorWorkspaceFade` from the two plan
   roots (mount is no longer the domain-switch event). Preserve spec §20's
   ~180–220 ms domain-switch feel with a CSS class-based opacity fade on the
   visible/hidden flip, honoring `prefers-reduced-motion`. The shared fade
   helper stays for genuine mount/unmount swaps (Plan ⇄ 3D, timeline,
   sidebars).
3. **State continuity checks** — pan/zoom persists per surface (component-local
   state survives); layout draft tool state unaffected (`layoutInteraction`
   lives outside); camera-plan drag/session state unaffected (`cameraPlan`
   owned by `EditorApp`); timeline playhead/height continuity (G3) untouched;
   boot-empty still clean.
4. **Perf watch** — hidden surface is `display: none`: no pointer-move rebuilds,
   no paint. Confirm no double rAF work from two live SVG models.

### Tests

- New contract (mirror of G3): both plan cells stay mounted across
  Scene ⇄ Camera; hidden one inert. Assert `EditorApp` renders both
  unconditioned-by-domain within the plan branch.
- Update the P1.7 fade contract test (its path list references the two plan
  roots' `transition:editorWorkspaceFade` — adjust to the new mechanism).
- Existing plan/camera-plan suites stay green.
