## Outcome

Camera sequence authoring is reconciled to the Camera-flow-specs mental model —
**Sequence = an ordered subset of the camera graph** — without touching the graph
engine or the visitor. The Sequence Inspector becomes the single reordering
surface (the timeline's redundant drag-connect path was already removed
2026-08-21, before this plan); the pinned `entrance-start` invariant becomes a
default so **Set as First** re-rooting works; every camera — sequenced or not —
gets a preview affordance; and the "Free Cameras" terminology is retired in favor
of **Unsequenced**.

The spec is ~90% ratified by shipped P1.5/P1.6 behavior (audited below). This
increment is the remaining delta: naming, re-root, membership/promotion policy,
and preview wiring. No new npm dependency, no schema change, no sampler/runtime
behavior change.

## Scope (pinned)

### 1. Terminology — retire "Free Cameras" → "Unsequenced" (spec §2, §4, §20)

Name change only; the model (`freeNodeIds` = nodes outside the chain) is
unchanged.

- `CameraFlowPanel.svelte`: section title "Not in order yet" → **Unsequenced**;
  "free nodes" aria/count labels, "Drag to flow" meta, and empty-state copy →
  unsequenced wording.
- `plan-camera-projection.ts`: `camera-free-badge` → `camera-unsequenced-badge`
  (style key + any copy); order labels unchanged.
- Mutator status copy ("…is now a free node" → "…is now unsequenced").
- **Amended 2026-08-21 during drafting:** `Design-shell-specs.md` §4, the
  visual spec §10, and P1.7 now use **Unsequenced** — P1.7 implements the
  sidebar with the new name (no further doc work; P3's conformance pass sees it
  already).
- Store accessor names (`freeNodeIds`) stay internal — no API churn.

### 2. Re-root — "Set as First" (spec §9, §13)

Unpin `EDITOR_GUIDED_TOUR_START_NODE_ID = 'entrance-start'` from a hard invariant
to a **default preference**. Role rule (owner, 2026-08-21): the constant defines
only the preferred/default start when resolving or seeding sequence state where
author intent has not overridden it — it no longer defines valid sequence
structure. Rename is optional; the comment at its definition must state this so
a future reader cannot restore the invariant from the name alone. Concretely:

**`editor-navigation-graph.ts`**

1. `validateGuidedTourOrder` — delete the `if (nodeById.has(EDITOR_GUIDED_TOUR_START_NODE_ID))`
   block (the `missing_guided_start` / `guided_start_not_first` checks). The
   seed preference in `mainFlowStart` stays, so untouched docs keep the entrance
   head.
2. `validateGuidedTourRemoval` — delete the `node.id === current.nodeIds[0]`
   rejection (`protected_guided_start`); head removal becomes valid (spec §12
   "Head — always valid"). Note this guard is **chain-head-based**, not
   id-based, so it is exactly the removal of the "pinned start" behavior.
3. `validateGuidedTourInsertion` — allow index 0 (spec §11 "Start and end are
   always real insertion positions"): relax the `index < 1` guard to `index < 0`
   and reword the message ("Choose a flow gap").
4. Failure-code union — remove the now-dead `missing_guided_start`,
   `guided_start_not_first`, `protected_guided_start`.
5. Doc-comment sweep + seed single-sourcing — update comments that still
   describe the pin (`validateCurrentGuidedTourOrder` "display order is pinned
   to entrance-start…", ~line 392; `mainFlowStart`; any timeline/projection
   comments referencing the start preference) and import
   `EDITOR_GUIDED_TOUR_START_NODE_ID` in `editor-camera-timeline.ts` (currently
   a duplicate `'entrance-start'` literal at default param).

**`CameraFlowPanel.svelte`** (Sequence Inspector)

- `draggable={index > 0 && …}` → head draggable too; move-up disabled `index <= 1`
  → `index === 0`; move-down disabled drops the `index === 0` clause; remove
  button drops the `index === 0` clause and the "Flow start is pinned" title.
- Add a **Set as First** action on non-head rows (spec §13 re-root vs reorder
  must stay visibly distinct): computes the forward suffix from the chain and
  calls `setGuidedTourOrder([nodeId, …suffix])` — consecutive pairs are chain
  links (always connected), earlier nodes are demoted to Unsequenced, one
  history entry via the existing mutator. No new mutator needed unless the
  suffix computation is moved store-side (`reRootGuidedTour`).
- The "Start" badge follows the head (already index-0 based).
- Head-gap promotion: expose a drop/promote target before the head row so an
  Unsequenced camera connected to the current head inserts at index 0 (the
  relaxed `index < 0` guard is dead code without this affordance). This is the
  path for "connected camera becomes first" (see Test impact, B-first case).

**`editor-camera-timeline.ts`** — **no code change**: `findGuidedStart` already
prefers `preferredStartNodeId = 'entrance-start'` and falls back to walking
`previousNodeId` links to the actual component head. Add a test pinning the
fallback when entrance-start is unsequenced or demoted to mid-chain.

**`plan-camera-projection.ts`** — order labels follow the new head (already
derived from the chain — verify on fixtures).

### 3. Membership ops + promotion policy (spec §6, §7, §11, §12, §22)

- Keep `insertNodeIntoGuidedTour` / `removeNodeFromGuidedTour` and the existing
  gap-drop + "+ Insert here" UI as the promotion paths.
- **Decision D2 — ratified 2026-08-21: strict.** No silent connection creation
  anywhere, insertion included. `insertNodeIntoGuidedTour` loses the S10.2
  one-missing-edge auto-create; a drop whose gap edges are not both present
  rejects and the copy names the missing pair (spec §5/§22 hold literally).
  Reorder/remove stay strictly no-auto-create (already true).
- Head removal + "Add to Sequence" contextual actions land with §2 (a demoted
  head is simply re-promotable at any connected gap).
- Spec §22: with D2 strict, insertion no longer bundles an auto-created edge —
  §22 holds uniformly, no exception documentation needed.
- **Decision D4 — minimum sequence length (ratified 2026-08-21: keep ≥ 2,
  documented deviation from spec §6).** The floor is a **runtime invariant, not
  just an editor policy**: the route compiler `walkFlowChain`
  (`camera-route.ts`) throws when a flow start has no `nextNodeId`, and the
  motion model is edge-based — a single-node flow would yield a zero-edge,
  zero-duration timeline (`createEditorCameraTimeline`), i.e. no playable tour.
  Spec §6's one-node case is therefore reclassified as an **authoring
  intermediate** (drag a camera in, connect the next) that the current
  seed-at-two UX already covers; the empty "Drop a camera here" state is served
  by the existing "No camera flow" copy. Consequence for D1: re-root /
  head-removal on a **two-node** chain stays guarded by the minimum ("Set B as
  first" on A→B cannot produce a one-stop sequence) — rejected with clear copy,
  never silent. The relaxation is **not planned as an increment**; its cost
  (relax both validators, teach `walkFlowChain` / timeline / preview a
  hold-only single-stop route, new remove/re-root UI guards) is recorded in Out
  of scope if product ever wants it.

### 4. Per-camera preview (spec §18)

`previewSelectedNode` / `previewSelectedConnection` / `previewSelectedTransition`
exist on the facade but are **wired to zero components** (audited 2026-08-21).
Wire them:

- **Preview Camera** context action on Sequence rows, Unsequenced rows, and the
  Camera Inspector — works for any node; `startNode` has no membership gate.
- **Preview Connection** for the selected connection (both directions).
- From Camera Plan, preview switches to Camera 3D **preserving selection**
  (existing shared-selection rule; `previewSelectedNode` already syncs the

- No engine change; the commands already handle unsequenced nodes.

Mostly ratification: sweep the failure codes (`missing_guided_connection`,

## Decisions to ratify (gates)

- **D1 — entrance-start pin → default (ratified 2026-08-21).** Change list in
  §2 above. Owner rationale: the pin models `entrance-start` as a permanently
  special node, which conflicts with the ratified model (Sequence = user-chosen
  ordered traversal through the graph); any-camera-first requires no hard
  invariant. Accepts that existing documents can re-root away from the entrance
  camera and remove the sequence head; the entrance node remains a normal graph
  node with its connections intact, the visitor entry default is untouched, and
  the relic inherits the new behavior (same store/panel — intended, contracts
  stay green). The constant survives only as preferred/default seed (see role
  rule in §2).
- **D2 — strict no-silent-creation everywhere (ratified 2026-08-21).**
  Insertion loses the S10.2 one-missing-edge auto-create; drops without both gap
  edges reject and name the missing pair. Spec §5/§22 hold with no exception.
- **D3 — terminology timing (executed 2026-08-21).** `Design-shell-specs.md` §4,
  the visual spec §10, and P1.7 were amended during P1.8 drafting, so P1.7
  implements the sidebar with the Unsequenced name. No further doc work.
- **D4 — minimum sequence length ≥ 2 (ratified 2026-08-21: keep).** Documented
  deviation from spec §6, grounded in the runtime (`walkFlowChain` throws on a
  node without `nextNodeId`; edge-based motion model). Re-root / head-removal on
  two-node chains stay guarded with clear copy. Relaxation not planned (see §3).

## Manual acceptance

1. In Camera domain, the sidebar shows **Sequence** + **Unsequenced** sections
   (no "Free"/"Not in order yet" copy); every camera appears in exactly one.
2. Select an unsequenced camera → **Preview Camera** works from the sidebar, the
   Inspector, and Camera Plan (Plan switches to Camera 3D, selection kept).
3. Right-click/action **Set as First** on a later sequence camera: forward suffix
   preserved, earlier cameras become Unsequenced, all connections intact; Undo
   removes the whole re-root in one step.
4. Drag an Unsequenced camera into an internal gap: valid only when both gap
   edges exist; invalid drops explain the missing pair. No connection is ever
   auto-created.
5. Remove a middle camera: rejected with the "no connection between" message when
   A—C is absent; head removal now succeeds and demotes the old head.
6. Play the tour after a re-root: playback starts at the new head; the visitor
   entry default is unchanged.
