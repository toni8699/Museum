## Goal

Replace the closed-loop "Guided Tour" authoring constraint with a **Camera Flow**
model: one ordered **main route** plus optional **detours** (bounded side paths
that return to their origin), built on the existing graph connectivity. The
normal authoring experience must not require the user to reason about graph
topology, and it must not require a loop.

```text
Main route = normal ordered playback      Start → A → B → C → E
Detour     = optional branch, returns     B → D → D2 → B
Graph      = underlying connectivity      (edges carry the authored motion)
```

The user-facing mental model:

```text
CAMERA FLOW
  Main Experience
    1  Entrance
    2  Gallery
    3  Piano
         Detours
           Piano Detail
           Piano Close-up
    4  Exit
  Free Nodes          ← exists in the graph, not on the flow
  Connections         ← Advanced
```

Explicit V1 boundary: **one ordered main route + detours that return to their
origin.** Arbitrary branch-and-merge (two detours independently continuing into
a later main node) is rejected by validation. This is not a general graph
editor.

## Why this is needed (the loop requirement is the bug)

Today, ordering is a closed reciprocal cycle (`nextNodeId` / `previousNodeId`),
and `validateGuidedTourOrder` demands a direct connection for every consecutive
pair **including the wraparound pair**. Consequence, confirmed live in QA:

- Append camera 3 to a 2-node cycle `1 → 2 → 1` requires edges to **both**
  `1` and `3`'s new neighbors, because the cycle must close back to the pinned
  start. That is the restrictive "connect to both" flow.
- The two-node seed (this session) is a degenerate 2-node *closed* cycle (both
  nodes point at each other) — the exact structure that caused the
  `each_key_duplicate` / broken-gizmo bug.

**Decision: the loop is no longer a persistence requirement — it is derived,
not a state.** The main route is an **open chain**; loop playback exists iff a
connection record joins the tail back to the head **and that record is not
already used by the ordered chain** (the distinct-connection test). The
closing connection is an ordinary, authored connection with real motion — no
closing of order links, no synthesized wrap. Graph connectivity stays the
carrier, ordering stays explicit, and the restrictive case disappears:

| Authoring | Closed cycle (today) | Open flow (S10.2) |
|---|---|---|
| Append node 3 after `1 → 2` | Edges to both `1` and `2` required | One edge (`2–3`), auto-created in the same transaction |
| Insert node between `1` and `2` | Both new neighbor edges required | At most **one** missing edge auto-created; the old `1–2` edge is retained as unused |
| Preview | Requires the closed cycle | Requires only the ordered chain |

## Current architecture (source of truth)

- **Nodes** carry `connectedNodeIds[]` (undirected adjacency) and
  `nextNodeId`/`previousNodeId` (order links).
- **Connections** are undirected edges with per-direction authored motion
  (`viewTracks.forward/reverse`, `timing.forward/reverse`) — a return is the
  same edge traversed reverse, no new representation needed.
- **Ordering source of truth is the persisted order links**, validated *against*
  the edge graph — not inferred from traversal. This split (order vs
  connectivity) is exactly what Camera Flow needs; it already exists.
- `getGuidedCameraRoute` walks the links and asserts one closed cycle covering
  all guided nodes; `createEditorCameraTimeline` and `canStartTourPreview`
  (`getCameraTimeline() !== null`) inherit that closure requirement.
- Branching in the raw graph is already legal (degree > 2, spurs); only the
  *ordered* structure is restricted to one cycle.
- Every graph mutation is one document transaction = one history entry.

## Data model change (the only new persisted state)

Keep the order links as the ordering primitive; relax the codec; add one field.

```text
Main route (open chain, persisted via links):
  A.previousNodeId = undefined      A.nextNodeId = B
  B.previousNodeId = A              B.nextNodeId = C
  E.previousNodeId = C              E.nextNodeId = undefined     ← open tail

Detour (open chain + origin marker on the head):
  D.detourOfNodeId = B              D.nextNodeId = D2            ← NEW field
  D2.previousNodeId = D             D2.nextNodeId = undefined
  edges: B–D, D–D2, D2–B            ← return edge validated (or auto-created once)

Free nodes: no order links, no detourOfNodeId.  (May still hold edges.)
```

- `nextNodeId` / `previousNodeId` semantics unchanged for ordered neighbors.
  Only the codec assertion changes: "both-or-neither / must close" →
  "each ordered component is a simple open chain; the loop is never a codec
  state — it is derived at playback from the connection graph."
- `detourOfNodeId` (optional, on a chain head) is the **only new persisted
  field**. The "Return" is not new state — it is the existing undirected edge
  `D2–B` traversed reverse, with per-direction motion already supported.
- No explicit `Continue` / `Detour` edge typing. A node's role is derived from
  which ordered component it belongs to: the component containing the pinned
  flow head = main; any other chain = detour; none = free.
- Backward compatibility: an existing closed-cycle document keeps its return
  edge as an ordinary connection; Loop derives (tail↔head record present and
  distinct from the chain), and "Once" playback stops at the tail instead of
  taking it. No data migration.

## Invariants

Flow structure:

```text
F1  Exactly one main route — the ordered component containing the flow head (pinned entrance-start for V1).
F2  Main route is a simple open chain (≤1 next, ≤1 previous per node, no repeats).
F3  The ordered chain contains each node exactly once — so its transition records are all distinct by construction (no parallel edges either); no instance/index tracking is ever needed.
F4  Zero or more detours; each is a simple chain whose head declares detourOfNodeId ∈ main route.
F5  Detour return: a direct edge exists from the detour tail to the origin. The return is NOT part of the ordered chain.
F6  Detour nodes have flow-degree ≤ 2 (origin+next / prev+tail→origin). No detour→future-main-node merge. (V1 rejection)
F7  Free nodes carry no order links; edges on free nodes are visible under Connections/Advanced.
```

Traversal and loop (locked review consensus):

```text
T1  Order determines traversal.
T2  Connections provide motion.
T3  Playback never chooses graph branches.
T4  Missing transitions stop playback at the last valid node, naming the missing pair. At most ONE missing edge may be auto-created per operation (existing drag-connect rule); list reorder is strict.
T5  Loop exists iff a last ↔ first connection exists (record identity) and that record is NOT already used by the ordered chain — the distinct-connection test, uniform for all N; no N=2 special case.
T6  Editing order never mutates connections.
T7  Unused connections stay authored (never auto-deleted).
```

## Locked architecture (review consensus, 2026-08-17)

Distinctness in the loop test is **connection record identity** (the record
ID), never a direction interpretation — the codebase's `findConnectionBetween`
already searches either orientation of an undirected record:

```text
Order: A → B            chain uses record #12 (A–B)
last = B, first = A     candidate closing record = #12 → already in chain → no loop

Order: A → B → C        chain uses #12 (A–B), #13 (B–C)
last = C, first = A     candidate closing record = #14 (C–A) → distinct → loop
```

| Dimension | Specification |
|---|---|
| Order representation | Reciprocal node links; atomic link rewrites, one history transaction |
| Connection representation | Undirected records with per-direction authored tracks/timings |
| Loop condition | Closing pair record exists AND is distinct from the chain's transition records |
| Reorder behavior | Eager validation on drop — reject invalid disconnects, or auto-bridge exactly one missing edge with a prompt |
| Missing transitions | Playback stops at the last valid node and names the missing pair |
| Repeated nodes | Forbidden in the ordered chain (each node exactly once) — the Figure-8 case cannot occur; chain transition records are distinct by construction, so no instance/index tracking |
| Viewport state | Inactive/retained connections render as desaturated dashed splines with a visibility toggle |
| Readout & controls | Explicit derived indicator ("Loops via: Piano → Entrance") with single-click [Disconnect Loop] |

**UI zones (from review) — ownership split across S10.2 and S10.1.** The
visual zones are S10.1 surface (specified in the S10.1 plan's S10.1.3/S10.1.4
increments); the microcopy ships with the S10.2 mutations (slice 3):

1. **Sequence Inspector** (S10.1.3/S10.1.4) — reorderable ordered-path list

### Mutation microcopy contract (ships in slice 3)

Every mutation posts its message through the existing status channel; loop
state changes are always announced, never silent:

| Operation | Message |
|---|---|
| Append (no loop) | "Added X after Y — the path now ends at X" |
| Append (loop was on) | "X is now the end of the tour. The loop from [tail] → [head] is inactive. Draw X → [head] to loop" |
| Insert (success) | "Added X between Y and Z" |
| Insert / reorder (strict reject) | "Missing transition: [from] → [to] — connect them first" |
| Reorder (drag, one auto-created) | "Moved X — created the missing transition [from] → [to]" |
| Remove from flow | "Removed X from the path — X is now a free node" |
| Add detour | "Detour added at X: [first node]" |
| Append detour node | "Added X to the detour at [origin]" |
| Remove detour / node | "Removed X from the detour — the camera node is kept as free" |
| Disconnect loop | "Loop disconnected — the path stops at X" |
| Loop appears | "The path now loops: [tail] → [head]" |
| Two-node pair | "Two-node path — add a third camera to create a loop" (only when asked; the loop row never renders for N=2) |

## Mutation semantics

Every operation = **one document transaction = one history entry**.

| Operation | Behavior | Edge handling |
|---|---|---|
| **Append main node** | Create standalone node, then link `tail.next = new`, `new.prev = tail` | Create the one missing edge in the same transaction |
| **Insert main node** | Splice links: `pred.next = new`, `new.prev = pred`, `new.next = succ`, `succ.prev = new` | Create ≤1 missing edge; **retain** old `pred–succ` edge as unused |
| **Reorder main** | Rewrite links only (current `setGuidedTourOrder`); reject with "connect first" if a consecutive pair lacks an edge | No creation (strict); drag-drop path may create one missing edge |
| **Remove from flow** | `pred.next = succ`, `succ.prev = pred`; node becomes free | No edge deletion |
| **Add detour** | Pick origin + node; set `head.detourOfNodeId = origin` | Create origin–head edge if missing |
| **Append detour node** | `tail.next = new`, `new.prev = tail` | Create edge if missing |
| **Reorder detour** | Rewrite links within the chain; origin untouched | None |
| **Remove detour node / whole detour** | Rewrite links; clear `detourOfNodeId`; nodes become free | No edge deletion; return edge remains an ordinary edge |
| **Delete camera node** | Existing splice (pred/succ relink) extended to detour chains; orphaned detour heads → delete the whole detour (documented rule) | Removes incident edges (existing behavior) |
| **Delete connection** | Refuse chain transitions and detour return edges (extend the current guided-edge refusal); allow deleting non-chain flow edges (the closing edge, chords, unused edges) | Unused and non-chain edges deletable |
| **Free → main** | Insert op with a free node | As insert |
| **Free → detour** | Add-detour with existing node | As add-detour |
| **Detour node → main** | Remove from detour + insert into main as **one combined transaction** | As insert |

**Loop is derived, not a mutation.** There is no Close-loop / Open-loop
operation: a closing connection is an ordinary connection (connect to create,
delete to disconnect). The UI's `[Disconnect Loop]` is a plain connection
deletion; playback reverts to Once when the derived test no longer holds.

**Never auto-delete edges.** Edges own authored motion (viewTracks, timing);
silent deletion destroys authored data. Retained-but-unused edges are surfaced
under Connections/Advanced and deletable there. Stale unused edges cannot make
playback ambiguous because playback follows order links, never raw traversal.

**Two-node seed change.** The current seed writes a degenerate 2-node closed
cycle. Under open chains it becomes an open pair `1 → 2` with one edge —
simpler, and it removes the degenerate both-directions case that caused the
`each_key_duplicate` / broken-gizmo crash.

## Risks / unresolved decisions

1. **Order links vs edge graph can drift.** Mitigated by validation on every
   mutation (already the pattern) + Connections/Advanced visibility +
   refuse-delete for flow edges. This is the standing cost of "user reorders
   route items, not edges."
2. **Silent edge deletion loses authored motion.** Never auto-delete; mark
   unused. Auto-create is safe (it only adds).
3. **"Flow" naming could invite general-graph expectations.** Contained by UI
   shape (tree + numbered list, never a node editor) and by validation
   rejecting branch/merge.
4. **Pinned `entrance-start` vs "Node 1 is just the first node."** Keep the pin
   for V1; un-pinning is a small validation change, later slice.
5. **Detour origin deleted** → delete the whole detour; one clear status
   message, one history entry.
6. **Open-chain timeline boundary** changes the ruler's final edge — the
   existing timeline tests pin the closed form and will need updating
   (contained, same slice).
7. **Loop is derived, so it must be visible and it follows the tail.** (a)
   Visibility: the closing record is not part of the ordered chain, so the UI
   must render the derived readout ("Loop closes via Piano → Entrance") —
   never a bare toggle. (b) Attribution: after a reorder, the loop may close
   via a different record than the one the user drew (still deterministic);
   the readout names the actual pair. (c) Follows the tail: appending or
   removing changes the tail, so the loop silently turns on/off; the tool
   announces the change ("Garden is now the end — connect Garden → Entrance to
   loop"). (d) N=2 never loops: the pair's only record is also its chain
   transition, so the distinct-connection test yields false — no special case,
   no auto-bounce.

## Non-goals (deferred)

- Multiple persisted Camera Flows (deferred; a detour is the stepping stone).
- Arbitrary branch-and-merge authoring.
- Un-pinning the flow head.
- Interactive visitor choice of detours.
- Automatic/synthesized loop wrapping at the playback layer — loop is always a
  real connection record the user authored (derived, never fabricated).
