# P21.6 Plan: 3D Camera Visualization & 2D–3D Spatial Unification

**Status:** Ratified implementation spec (owner rulings 2026-09-06 applied; final closeout slice of P21 — not a registered tracker P-number)  
**Authority:** `docs/plans/2026-09-04-P21-unified-project-shell-spatial-reconciliation.md` + `docs/Design-specs/Design-specs.md` §10/§28 + `theme.md` (Spatial Invariants).  
**Objective:** Eliminate 3D camera visual noise, unify 3D camera nodes and paths with the 2D Plan standard across all themes, retire the yellow wireframe "object box" body proxy, and implement the ratified translucent cinematic frustum.

---

## 1. Fieldwork Reconciliation & Root Causes

Based on the verified codebase audit, 3D camera visualization currently suffers from four structural flaws:

1. **Theme Contamination & Hardcoded Hexes:** Zero 3D camera components read from `SCENE_PALETTE` or CSS variables. All helpers use hardcoded golds (`0xd6b35f`, `0xffcf67`, `0xffe29a`), light blue (`0x5bc8ff`), and pink (`0xff9ed2`). Because they are hardcoded, they clash with light mode (`porcelain-atelier`), clash with the 2D Plan standard, and drift between themes.
2. **The "Selection Outline Box" Unmasked:** The box appearing around selected cameras is **not** an object selection outline (`SelectionOutline` / `BoxHelper`). It is the virtual-camera body proxy in `lib/editor/camera/EditorCameraFramingHelpers.svelte:32-42`:
   ```ts
   const bodyGeometry = new BoxGeometry(0.28, 0.2, 0.38);
   const bodyMaterial = new MeshBasicMaterial({ color: 0xffcf67, wireframe: true, ... });
   ```
   A wireframe yellow crate appearing at the camera eye looks like a raw debug bounding box.
3. **The "Circus of Floating Spheres":** Up to 5 independent sets of spheres populate the 3D viewport simultaneously:
   * Gold octahedrons at nodes (`EditorCameraHelpers:36`)
   * Light-blue target spheres (`EditorCameraHelpers:37`)
   * Pale-gold path anchors (`EditorCameraPathHelpers:128`)
   * Gold FOV handles floating on the frustum edges (`EditorCameraFramingHelpers:57`)
   * Pink/blue view keyframe spheres (`EditorCameraViewHelpers:86,125`)
4. **Hollow Wireframe Frustum:** The frustum in `EditorCameraFramingHelpers.svelte` is 1px monochrome gold lines with **zero face fill**. It fails to communicate the camera’s spatial volume or field of view as an intersecting light cone.

## 2. Core Architectural Invariant: 2D–3D Spatial Parity

> **Sacred Rule:** Camera nodes and routes represent **authored spatial truth**, not UI chrome.  
> Just as the 2D Plan canvas is invariant `#F5F3EE` across all themes, **3D camera visualization must be identical across all themes.**

* **Sequenced Nodes:** Solid brand blue (`#2F8CFF` / `0x2f8cff`), white sequence number, crisp white keyline.
* **Unsequenced Nodes:** Emerald ring (`#10B981` / `0x10b981`), transparent center.
* **Camera Paths:** Solid brand blue (`#2F8CFF` / `0x2f8cff`), selected path highlighted (`#55A1FF` / `0x55a1ff`); retained/inactive paths keep today's gray dashed line (`0x8a8a8a`) — no second retained language.
* **Frustum Volume:** Translucent electric-blue face fill (`8–10%` opacity) with crisp blue silhouette edges.

### Slice 2: Retire the Wireframe "Object Box" & Redesign Camera Body

#### 2.1 Kill the Wireframe Box Proxy
In `lib/editor/camera/EditorCameraFramingHelpers.svelte:32-42`:
* **Delete:**
  ```ts
  // DELETE THIS:
  const bodyGeometry = new BoxGeometry(0.28, 0.2, 0.38);

Replace the wireframe shipping crate with a minimal dark apex nub that grounds the frustum rays (owner ruling: minimal nub, not a modeled barrel). Unlit material only — `MeshStandardMaterial` with metalness and no envmap renders near-black under museum lighting:

  const apexMaterial = new MeshBasicMaterial({ color: 0x1e293b }); // dark graphite, zero lighting risk
  ```
* The nub is anchored to the camera node position and oriented along the camera forward axis, meeting the apex of the frustum rays.

### Slice 3: Translucent Cinematic Frustum & Look-At Ray

Transform the line-only gold cage in `EditorCameraFramingHelpers.svelte` into a volumetric, cinematic frustum matching Reference Image 1.

```text
CURRENT IMPLEMENTATION (Gold 1px Wire Cage):
     Eye ────────── Corner
      │ \          / │
      │   \      /   │   (Hollow, no depth cues, monochrome gold 0xffcf67)
      │     \  /     │
      └────── Corner ┘

TARGET REWORK (Cinematic Frustum):
     Eye (Lens Apex)
      ▲ \  [Translucent Electric-Blue Fill (8–10% opacity)]
      │   \  
      │     \==== [Dashed Look-At Ray] ========> [Target Crosshair/Reticle]
      │       \
      └──────── [Crisp 2px Perimeter Vectors #2F8CFF]
```

#### 3.1 Translucent Frustum Volume Mesh
In `lib/editor/camera/editor-camera-framing.ts` and `EditorCameraFramingHelpers.svelte`:
* Construct a 4-sided pyramid mesh connecting the eye $(0, 0, 0)$ to the 4 far-plane corners:
  * Left Face: `[Eye, TopLeft, BottomLeft]`
  * Right Face: `[Eye, BottomRight, TopRight]`
  * Top Face: `[Eye, TopRight, TopLeft]`
  * Bottom Face: `[Eye, BottomLeft, BottomRight]`
* Far Plane Face: `[TopLeft, TopRight, BottomRight, BottomLeft]`
* **Material Configuration:**
  ```ts
  const frustumFillMaterial = new MeshBasicMaterial({
    color: SCENE_PALETTE.cameraFrustumFill,
    transparent: true,
    opacity: 0.09,
    depthWrite: false,
    depthTest: true,
    side: DoubleSide
  });
  ```
  *(Setting `depthWrite: false` ensures scene objects and artworks inside the museum are visible through the frustum cone without sorting artifacts).*

#### 3.2 Crisp Silhouette Edge Lines
* Restyle the boundary rays and far-plane rectangle to canonical blue:
  ```ts
  const frustumLineMaterial = new LineBasicMaterial({
    color: SCENE_PALETTE.cameraFrustumLine,
    transparent: true,
    opacity: 0.75,
    depthTest: false,
    depthWrite: false
  });
  ```

#### 3.3 Dashed Look-At Ray & Target Reticle
* In `EditorCameraHelpers.svelte:53-56`:
  * Replace the solid beige line (`0xe9dfc5`) with a slate dashed look-at line (`SCENE_PALETTE.cameraLookAtRay` = `#94A3B8`, **not** white — white reads as selection against the white node keylines):
    ```ts
    const lookAtMaterial = new LineDashedMaterial({
      color: SCENE_PALETTE.cameraLookAtRay,
      dashSize: 0.25,
      gapSize: 0.15,
      transparent: true,
      opacity: 0.45,
      depthTest: true
    });
    ```
  * `LineDashedMaterial` requires line distances: call `connector.computeLineDistances()` after every points update in `updateConnector` (the geometry is rewritten per frame — without this the dashes render wrong).
* Target marker (`EditorCameraHelpers:37`):
  * Replace the solid light-blue sphere (`0x5bc8ff`) with a clean target reticle (a subtle outer ring $r=0.15\text{m}$ with a small center dot in `SCENE_PALETTE.cameraTarget`).

#### 3.4 FOV Handles Stay Mounted (progressive disclosure rejected for P21.6)
* Owner ruling: keep the FOV handles mounted on the selected frustum — dragging them is the primary (and only) direct-manipulation FOV gesture in 3D (`EditorSelection.svelte:358` resolves drags from `camera-fov-handle` userData); there is no standalone Frame tool mode to gate them behind, so hiding them removes the affordance.
* Streamline instead: shrink `SphereGeometry(0.13)` → `0.09`, recolor to palette blue `#2F8CFF`. The frustum mounts only for the single selected camera, so two compact handles add no clutter.

### Slice 4: De-Clutter Floating Spheres & Unify 3D Nodes with 2D Plan

Bring the 3D camera nodes into direct 1:1 visual continuity with the newly polished 2D Plan nodes.

#### 4.1 3D Camera Node Representation (Sequenced vs. Unsequenced)
In `lib/editor/camera/EditorCameraHelpers.svelte:36-50`:
* Replace the gold octahedron (`0xd6b35f`) with a dual-layer node marker:
  1. **Inner Core (Spherical / Disc Mesh):**
     * Sequenced: Solid Blue `SCENE_PALETTE.cameraNodeSeq` (`#2F8CFF`).
     * Unsequenced: Transparent center with emerald perimeter `SCENE_PALETTE.cameraNodeUnseq` (`#10B981`).
  2. **3D Sequence Number Presentation:**
     * Restyle the existing HTML overlay badges (`EditorCameraLabelProjector.svelte` + `EditorCameraLabelsOverlay`, P1.7 shell spec "Viewport MUST show") to the 2D Plan badge grammar: solid blue disc `#2F8CFF`, 1.5px white border, white tabular numeral. No Canvas-sprite machinery — the projector already publishes per-node screen positions every frame.
  3. **Selection State:**
     * When selected, render a concentric 3D selection ring ($r=0.28\text{m}$, color `SCENE_PALETTE.cameraNodeSeqActive`) around the node. Never turn the node black or yellow!

#### 4.2 Prune Path Anchors
In `lib/editor/camera/EditorCameraPathHelpers.svelte:128-148`:
* Path anchors currently render as large pale-gold spheres (`SphereGeometry(0.14)`, `0xffe29a`).
* **Fix:**
  * Reduce the visible radius from `0.14m` to **`0.07m`** (50% size reduction).
  * Color: `SCENE_PALETTE.cameraAnchor` (`#E2E8F0` / `0xe2e8f0` off-white/slate).
  * On Hover: Pop to `0xffffff` and scale up to `0.10m`.
  * Preserve grab-feel with an invisible pick shell: a second `SphereGeometry(0.14)` mesh on the same root with `colorWrite: false` (precedent: the path pick corridors in the same file) — the clickable area stays today's size while the visible dot shrinks. Do not ship a pure shrink with no pick compensation.
  * Result: Anchors read as delicate spline control points rather than distracting yellow balls.

#### 4.3 Clean View Keyframe Markers
In `lib/editor/camera/EditorCameraViewHelpers.svelte:86,125`:
* Replace unratified pink (`0xff9ed2`) and light-blue (`0x79d8ff`) spheres with the canonical palette:
  * View Key Marker: Diamond glyph in `SCENE_PALETTE.cameraPathSelected`.
  * Target Marker: Crosshair in `SCENE_PALETTE.cameraTarget`.
