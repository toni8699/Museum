**Pre-flight drift guard (run immediately before the strings pass — P7.1–P7.5

cd apps/museum
L=$(rg -n -i '\bmuseum\b' src tests vite -g '!src/lib/museum/**' -g '!src/routes/museum/**' -g '!tests/lib/museum/**' | wc -l)

If either count differs, **re-inventory before trusting the buckets** — at
minimum diff the new grep output against §4's P/T line lists and re-bucket
any new/moved R lines. The §4 line numbers are snapshot references; the
enforcement that actually matters is content-based (§7 greps), so the guard
is cheap insurance against a silently drifted checklist, not the pass's
backstop.

## 2. Decision rule (operationalizes §5 policy)

§5 policy: *editor-internal prose is reworded in the strings pass;
product/relic references are tolerated and documented.*

For each bare occurrence, ask **what does it denote?**

| If the occurrence denotes… | Bucket |
|---|---|
| live-editor vocabulary/prose/strings — a renamed file's path, a §2 code-adjacent string, an editor-internal comment, user-visible editor copy, CSS token, DnD MIME, or any test mirror of the above | **R — reword** |
| the relic: `$lib/museum/**` imports, `/museum` route refs (hrefs, test source-reads), keep-list names as bare forms (`virtual:museum-editor-entry`), production asset URIs under `/museum/`, boundary-assertion regexes, package identity, fixture URIs/hosts in the `/museum` domain | **P — relic-path tolerated** |
| the product/brand: browser & dev-route titles, the app-bar title, link text ("Preview Museum", "Back to museum"), dev-route headings, relic-reference comments & test descriptions, product data, arbitrary free-text fixture titles | **T — product-prose tolerated** |

Tolerated entries are *documented*, never edited. If a line carries two bare
occurrences of different buckets, both are listed on that line.
