## 1. User outcome and cut line

`▶ Preview` opens `/project/:id/preview` over the current unsaved draft,
including guest projects. A full-bleed visitor canvas replaces all Spatial
chrome. The sole shell overlay reads `VISITOR PREVIEW · Viewing Current Draft`
and provides `Exit Preview (Esc)`. Exit restores the same authoring session.
Preview requires neither cloud Save nor authentication.

P21 uses **keyboard/default spatial navigation only**. Bindings are:

| Input | Authored-camera mode | Zero-node orbit mode |
| --- | --- | --- |
| Left / Right | Previous / next valid Sequence link; ignore key repeat | Unbound |
| W / S / A / D | Look up / down / left / right | Unbound |
| Primary (left) button drag | Look; capture pointer until release/cancel | Orbit |
| Middle drag / wheel | Unbound | Dolly / zoom |
| Secondary (right) button drag | Unbound | Pan |
| Up / Down / Space / Backspace | Unbound | Unbound |
| Escape | Exit Preview | Exit Preview |
| Tab / Shift+Tab; Enter / Space on a button | Native focus and activation | Native focus and activation |

Navigation/look keys apply only with canvas focus, without Ctrl/Meta/Alt,
and never to editable fields or buttons. Consume handled keys only; unbound
keys do not invoke editor actions. Escape belongs to the takeover host.
No bottom menu, node chooser, Play Tour, timecode, Timeline, or Experience UI.
A short accessible canvas description explains the controls. Disconnected
cameras are not silently connected. No cameras means a neutral perspective
camera with existing orbit controls framing compiled content; empty projects
remain valid. Legacy MuseumHUD/CameraDirector bindings remain unchanged.

Hub work is the strict full-height owned-project table and guest callout.
No Recent shelf, covers, fake local drafts, Experience, Assets workspace,
Publish, schema migrations, new persistence, or deployment work.

## 3. Owner, snapshot, and new interface

`ProjectShellHost` remains the layout-owned host of one `EditorApp`. It passes
surface intent derived from the URL. `EditorApp` retains the session and renders
either its existing authoring subtree or `lib/visitor/VisitorPreviewSurface.svelte`.
The preview route page is intent-only, as the Spatial page is today.

New presentation state: surface intent, one captured return record, one validated
preview bundle, entry error and return focus target. No new dependencies,
document fields, selection/history store, graph resolver or motion engine.

The surface receives only detached runtime scene, compiled layout geometry,
room registry, navigation graph, read-only texture resolver, reduced-motion
preference, and an exit callback. It creates its own transient visitor camera
state. No EditorStore, LayoutPreviewState, history, selection or API client props.
Use existing exported types; do not create a generic session framework.

Entry transaction:

1. Finish neither a drag nor a draft implicitly. Disable entry during active
   gestures, invalid layout, bootstrap/Load/document replacement and pending
   save/auth handoff. Give the existing error/status surface a concrete reason.
2. Compose current Scene + Layout + current project name/ID; validate and derive
   a detached bundle. Never serialize the layout state's stale Scene copy.
   Call a separate `computeVisitorPreviewBlocker` in the editor-side preview
   coordinator, returning a reason or null. It checks the busy/gesture conditions
   above, project/geometry validation, and availability of referenced textures
   through the existing read-only source resolver. Local/package/project-asset
   references require retained bytes (`BinaryTextureStore.has` followed by actual
   resolution); accepted catalogue/static sources use the existing loader.
   Unsupported or unresolved required sources block entry. Do not call
   `computeCloudSaveBlocker`: ownership, upload readiness and cloud URI eligibility
   are irrelevant when the snapshot can render from retained local bytes.
   Keep this predicate out of the visitor import closure.
3. Capture return state before any viewport teardown. If validation or required
   asset resolution fails, remain in Spatial with the session untouched.
4. Freeze authoring interactions and Camera preview progression, push the preview
   URL, unmount Spatial chrome/viewports and mount the isolated visitor surface.
   Pending registry uploads may finish in the owner; they cannot replace the
   detached snapshot or be rolled back on exit.

Return record covers domain, shared Plan/3D view, Layout/Arrange mode; active
selection owner and Scene/Camera/Layout selection; both Plan pan/zoom/tool states;
Camera observer/POV and orbit position/target/projection/damping; Timeline scope,
playhead, transport state, dock expansion and scroll; viewport visibility toggles;
and focus. Document/history stacks, dirty baselines, project identity, name draft,
auth/save state and asset contexts stay in the mounted owner, not cloned back.

Capture component-local camera pose before teardown and restore before the first
visible frame. Existing `EditorCameraRig` unmount and `setWorkspace` preview-stop
behavior must not run as an ordinary domain exit during takeover. A running
Camera preview is suspended at its captured playhead and resumes from there
on return; a paused one remains paused. Preview time never advances authoring time.
Input suppression uses the same takeover flag, set before URL navigation and
surface teardown. Add optional `isSuppressed: () => boolean` to
`EditorShortcutHost`; `createEditorShortcutHandler` returns immediately when it
is true, before `preventDefault`, Escape, Undo/Redo or any mutation. `EditorApp`
passes the live flag through `registerEditorShortcuts`; the relic omits it.
Keep suppression active until Spatial state/focus restoration completes.

Window-listener inventory (under `lib/editor/`):

| Owner | Takeover handling |
| --- | --- |
| `hooks/shortcuts.svelte.ts` window keydown, retained with EditorApp | Explicit live suppression callback above |
| `app/ProjectRow`, `EditorProjectMenu`, `EditorViewportToolbar`, `UnifiedProjectTree` outside-click handlers | Unmount with authoring chrome; existing cleanup removes pointerdown/keydown listeners |
| `context-menu/ContextMenu` capture pointerdown/keydown + blur/scroll/resize | Close menus before capture and unmount; remove all listeners |
| `placement-ghost` capture pointermove/keydown | Entry blocks active placement; unmount removes listeners |
| `camera/EditorCameraTimelineFrame` resize pointermove/up/cancel and menu pointerdown/keydown | Entry also blocks local resize; `onDestroy(stopResize)` and menu effect cleanup remove listeners |
| `camera-plan/CameraPlanViewport`, `gizmo/EditorTransformControlsHost`, `EditorSelection`, `camera/EditorCameraTimelineDots` capture keydown/keyup/blur | Unmount with Spatial, using existing cleanup |

No additional flag is needed for correctly unmounted descendants. Verify their
cleanup and include any remaining authoring portal in that subtree; a retained
portal must receive the same suppression flag. Release pointer capture at teardown.
Keep the session's beforeunload dirty guard active; it is not an authoring shortcut.

Navigation uses SvelteKit hooks, not a new raw popstate listener.
`useEditorShellBoot` already owns `beforeNavigate`: add an optional retained-session
navigation predicate, default false for the relic. Exempt only the same project
ID's Spatial↔Preview routes from discard confirmation; project changes, Hub and
other destinations keep the existing guard. Do not restore state in
`beforeNavigate`, because another guard may cancel navigation.

`ProjectShellHost`'s existing `afterNavigate` handles successful navigation,
including browser Back/Forward, and drives a single idempotent surface reconciler.
Preview→Spatial disposes visitor resources and restores the captured record once,
before revealing Spatial and restoring focus. Entering Preview from a retained
Spatial session preflights/captures once, including Forward. Failed Forward entry
replaces the URL with Spatial and shows the reason; it never exposes partial
preview state. Guard against overlapping transitions and canceled entry navigation.

Exit button and Escape request the same Spatial route through `goto` with
`replaceState: true`; they do not independently restore or assume a history entry.
Browser Back uses the URL destination normally. All successful same-project exits
converge on the reconciler. Do not reinstall documents, clear history, mark saved,
or replay selection actions that seek Timeline. Project departure uses ordinary
owner teardown after the dirty guard accepts it.

Direct navigation/refresh to `/preview` has no in-memory snapshot. The mounted
`ProjectShellHost` captures a transient `previewEntryNotice`, redirects with
`goto(spatialUrl, { replaceState: true })`, and passes the notice to the restored
Spatial surface as a dismissible `role="status"` message: “Preview needs an open
draft. Open your project, then choose Preview.” It survives that same-ID redirect;
no storage, query string or backend channel is needed. Hide the preview surface
until preflight succeeds. Do not silently load cloud data or present a blank
replacement as the lost draft. Preserve explicit bootstrap intents for Spatial.
A→B navigation destroys A's owner, snapshot, requests and assets; late A results
cannot install into B. Same-project surface navigation never destroys the owner.

## 4. Visitor rendering and boundaries

Use snapshot-derived layout geometry and room registry, never `rooms.ts`/Chopin
fallback rooms. Preserve room-local transforms, model scale, materials, textures,
lights and authored visibility. Editor-only hidden/selection overlays are not
visitor content. Geometry issues block entry instead of rendering misleading
fallback rooms. Generated camera endpoints remain derived and never persist.

Start at the authored Sequence entry when present, otherwise the first valid
camera in document order. Zero-node projects take the neutral camera branch;
never call `getNode('')`. Movement follows `camera-route.ts` and
`camera-motion.ts` only. Generic look-around works in arbitrary room IDs;
legacy Paris restrictions remain in the legacy adapter. Respect reduced motion.

Keep both Plan cells' existing mounted/inert behavior while Spatial is active;
the complete Spatial surface unmounts only for takeover. No Plan authority
changes: X/Z/yaw only, Y preserved, no scaling or cross-owner gestures.
`/museum` and `/museum/editor` remain behaviorally frozen; no new layout-driven
runtime is installed into those routes.

Name the new gate `apps/editor/scripts/verify-preview-surface.mjs`. Export a
small graph validator called by an Editor Vite/Rollup build plugin in
`apps/editor/vite/preview-surface-boundary-plugin.ts`, registered in
`apps/editor/vite.config.ts`. In `generateBundle`, walk module information from
the resolved VisitorPreviewSurface root through `importedIds` and
`dynamicallyImportedIds`, before relying on output chunk grouping. Missing root,
unresolved internal edges and forbidden runtime modules fail the build.

Use Vite/Svelte's resolved, transformed module graph: it handles `$lib`, relative
and workspace imports, `.svelte` modules, re-exports and literal dynamic imports;
TypeScript type-only imports are erased. Do not build a regex source parser.
Reject unresolvable computed dynamic imports in this isolated closure; include
fixtures for alias/Svelte indirection, dynamic imports, allowed erased type imports
and a forbidden indirect runtime import. Retain source IDs in diagnostic paths.

Reject editor session/selection/history/gizmo/Inspector/Timeline modules,
bespoke MuseumScene/MuseumHUD and runtime Chopin defaults. The root is
`lib/visitor/VisitorPreviewSurface.svelte`, **not** the whole preview route or a
shared output chunk containing the retained owner. The existing standalone
`verify:visitor-bundle` remains a separate manifest-based gate.

CI hook: the plugin throws during `npm run build -w @portfolio/editor`, so root
`npm run build`, `build:editor` and the Vercel build all enforce it automatically.
There is no checked-in `.github` workflow to extend; no new CI system is needed.
Validator fixtures run in the existing Vitest suite.

## 5. Hub and entry flows

Reuse the existing API and ownership behavior. Authenticated Hub lists owned
cloud projects by last modification descending, with name, version, modification,
location/status and Open. Cover loading, empty and request-failure states.
Guest Hub shows temporary-session copy, Google sign-in and one-click New;
no draft records or resume promise. New immediately opens a fresh Spatial project.

Preserve `/` guest entry and authenticated Projects trampoline, `/editor`
compatibility redirect, OAuth `intent=projects|save`, owned Open `?load=1`, and
pending Save `?resume-save=1` with existing one-shot URL cleanup. Preview adds
no new OAuth or backend behavior. Hub navigation retains the current unsaved-work
policy; it is not the same-session Spatial/Preview round trip.

## 7. Fallback and closeout

and closure gate → takeover/restore → Hub and integrated acceptance. Keep Preview
disabled until the lifecycle and isolation checks pass. If the renderer extraction
expands, finish that checkpoint separately without weakening snapshot fidelity or
shipping a bespoke museum fallback. No new numbered slice is required.

there is no data migration. P21.4 remains pending until implementation and checks
