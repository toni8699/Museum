## 1. Outcome and cut line

For an authenticated owned project:

```text
PNG/WebP/JPEG file
→ P20.1 register + upload
→ ready registry asset
→ /project-assets/{assetId}
→ existing SceneTextureAsset registration
→ existing Spatial assignment/render path
```

P20.2 accepts **new cloud-file imports** and already-ready registry assets.
P20.3 owns conversion of existing `/local/...` and package-backed texture
references, cloud-Save readiness, and portable package export. P20.4 owns
automatic refresh/Load resolution. Therefore a P20.2 logical URI may render in
the current session but remains cloud-Save-blocked until P20.3.

No final Assets workspace, GLB import, provider search, delete/GC, dedup,
presigned URLs, public delivery, background upload, or new placement command.

## 2. Current seams to reuse

| Surface | Existing seam | P20.2 use |
| --- | --- | --- |
| Auth/project context | `EditorApp.svelte`: `projectApi`, `sessionStatus`, `projectId`, `ownedProjects`, request token + abort patterns | Gate registry work to current authenticated owned project; discard stale results on project/session change |
| API client | `project-persistence.ts`: credentialed `requestJson`, normalized origin, typed error mapping | Add asset metadata/list/register/upload/content methods; no second HTTP client |
| Texture UI | `EditorAssetLibrary.svelte`: Textures tab, local file picker/dropzone, MIME sniff, submit state | Add smallest `Cloud file` source beside Public URI / Local file |
| Session bytes | `BinaryTextureStore.register(uri, bytes, mime)` | Prime `/project-assets/{assetId}` bytes after upload/fetch so current renderer uses existing injected loader |
| Scene registration | `EditorStore.registerTexture` → `EditorTextureLibraryController.registerTexture` → `materialResourceMutator.registerVerifiedTexture` | Reuse after bytes are primed; one existing undoable Scene transaction |
| Spatial use | texture drag MIME + `requestTextureAssignment` | Unchanged; no cloud-specific assignment/placement path |
| Thumbnail | `EditorAssetLibrary.svelte` currently renders `<img src={texture.uri}>` directly | Resolve through `BinaryTextureStore.objectUrlFor(uri) ?? uri`; no raw private/API URL in scene state |
| Runtime texture | editor boot injects `BinaryTextureStore` ahead of public fetch | Reuse; no visitor loader change |

P20.1 HTTP contract is fixed: list, register, metadata read, raw upload, and
authorized content GET under `/projects/:projectId/assets`.

## 3. Decisions

### D1 — No built-in registry rows

Built-in models, shapes, lights, and public catalogue textures keep current
catalogue/public-resource behavior. P20.2 creates no `storage_kind='none'`
row. Registry rows begin only with explicit cloud-file ingest. This follows S0
ownership: catalogue owns built-in provenance and deterministic authoring
metadata; registry owns accepted project files.

### D2 — App root owns remote lifecycle; editor store stays document-only

Keep registry metadata and requests in `EditorApp.svelte`, beside project
persistence. Do not add a registry controller/store or put auth/network state
in `EditorStore`. Pass narrow data/actions through `EditorSidebar` to
`EditorAssetLibrary`:

```ts
projectAssets: readonly ProjectAssetMetadata[]
projectAssetsStatus: 'unavailable' | 'loading' | 'ready' | 'error'
retryableProjectAssetId: string | null
onUploadProjectTexture?: (name: string, bytes: Uint8Array) => Promise<string | null>
onRetryProjectTexture?: () => Promise<string | null>
onAcceptProjectTexture?: (assetId: string) => Promise<string | null>
```

Exact prop names may follow local naming, but no context/provider or second
state authority is warranted.

### D3 — Extend `ProjectApi`; reuse request/error policy

Add `ProjectAssetMetadata` plus methods to the existing `ProjectApi`:

```ts
listAssets(projectId, signal?)
registerAsset(projectId, name, signal?)
uploadAsset(projectId, assetId, bytes, signal?)
loadAssetContent(projectId, assetId, signal?)
```

JSON calls reuse `requestJson`. Raw upload uses one small sibling request
helper with a `Uint8Array` body, `Content-Type: application/octet-stream`,
`credentials: 'include'`, shared abort handling, and shared status mapping.
Client code does not set forbidden `Content-Length`; browser computes it from
the fixed-size body. Verify P20.1 receives it before implementation. If target
runtime does not expose it, amend P20.1 first without weakening the 25 MiB
bound. Content GET returns validated MIME plus `Uint8Array`; it never returns
or persists an API/R2 URL.

### D4 — Upload then accept; never mutate scene early

`onUploadProjectTexture`:

1. validate current authenticated owned-project identity and sniffed bytes;
2. register metadata, retaining returned `assetId`;
3. upload bytes to that same ID;
4. require returned `ready` metadata;
5. prime `BinaryTextureStore` at `/project-assets/{assetId}`;
6. call existing `store.registerTexture(name, logicalUri)`;
7. refresh registry list.

Upload failure leaves pending/failed metadata and no Scene mutation. `EditorApp`
retains one bounded retry record `{ projectId, assetId, name, bytes }`; retry
reuses that asset ID. New file selection replaces the retry record. Project
switch/sign-out/unmount clears it. A later fresh-file attempt may create a new
row; P20 ships no cleanup.
If Scene registration fails after upload, ready asset remains unreferenced and
available for explicit acceptance from the registry list.

`onAcceptProjectTexture` handles a ready unreferenced asset: authorized content
GET → verify MIME/bytes → prime `BinaryTextureStore` → existing
`store.registerTexture`. Exact logical-URI duplicates reuse the existing Scene
texture and create no history.

### D5 — Registry list is contextual, not a new workspace

Textures tab shows current project's registry assets below existing import
controls. Ready rows offer `Use texture`; pending/failed rows show status.
Retry upload is offered only while matching bytes remain in current picker
state. Search covers metadata name and logical URI. No pagination, modal,
wizard, management actions, or project-wide navigation.

### D6 — Stale work cannot cross project boundaries

Every list/upload/accept operation captures project ID plus request token.
Abort on unmount, sign-out, project replacement, and newer same-kind request.
Before priming bytes or mutating Scene, re-check token, authenticated session,
current project ID, and ownership. Stale completion is discarded. Switching
projects clears registry metadata/error/pending retry state.

### D7 — Existing history and selection semantics win

Remote register/upload/list/fetch creates no editor history. Acceptance creates
exactly one existing Scene texture-registration transaction. It does not select
an entity, assign a material, or start placement. Later drag/drop assignment
uses existing `requestTextureAssignment`, selection, and history behavior.
Undo removes only Scene registration/reference; durable registry row remains.

   strict readers, four `ProjectApi` methods, one raw-response helper.
2. `apps/editor/src/lib/editor/app/EditorApp.svelte` — current-project registry

3. `apps/editor/src/lib/editor/app/EditorSidebar.svelte` — narrow prop pass-through.
4. `apps/editor/src/lib/editor/EditorAssetLibrary.svelte` — Cloud file source,

5. Tests only where behavior lands. No shared-package, API, schema, renderer,
   visitor, relic, layout, camera, selection, or placement implementation.

## 5. Mount/unmount and project semantics

- Guest, unauthenticated, unconfigured, unsaved, or foreign project: cloud
  source unavailable; Public URI and Local file behavior unchanged.
- A project is owned only when current `projectId` appears in latest accepted
  `ownedProjects`; string shape alone proves nothing.
- First successful Save may establish ownership; refresh assets afterward.
- Explicit Load/project replacement aborts old registry work before document
  replacement and then loads new metadata.
- Unmount/sign-out aborts requests and clears retry bytes/metadata. Existing
  `BinaryTextureStore` lifecycle retains only URIs referenced by current Scene.
- `/museum/editor` receives no registry props/state/client calls. `/museum`
  receives no imports or private requests.

## 8. Boundaries and fallback

- Scene schema stays `{ id, name, uri }`; logical URI is
  `/project-assets/{assetId}` only.
- No R2/API URL, registry metadata, readiness state, or bytes enter
  `ProjectDocument`.
- No second placement, assignment, selection, history, texture cache, or
  renderer path.
- P20.3 owns existing-local/package conversion, cloud-Save-ready proof, and
  package export. P20.4 owns automatic Load-time byte resolution.

If browser raw-upload constraints require API change, stop P20.2 at client
list/register/read and amend P20.1's upload contract first. Otherwise rollback
is client-only: remove Cloud file/list wiring; existing local/public texture
flows and durable API rows remain valid. No destructive DB rollback.
