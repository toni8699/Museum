# P1.9 — Camera sidebar simplification (neighbor dropdown · drag-only reorder · empty-chain promotion)

**Date:** 2026-08-21
**Status:** Approved — folded into P1 as the final slice (tracker [`docs/plans/README.md`](README.md))
**Tracker:** P1 umbrella [`2026-08-18-P1-camera-overhaul.md`](2026-08-18-P1-camera-overhaul.md) — **P1.9**, depends on **P1.8**

## Rationale

The shipped Camera Sidebar (S10.2 / P1.7 / P1.8) drifted from the canonical shell
spec. `Design-shell-specs.md` §4 prescribes Sequence rows exposing *order number,
camera name, drag reorder, selection, visibility, contextual actions* — nothing
more — while the implementation added:

- a per-row move-arrow cluster (↑/↓) that was never spec'd (`Design-specs.md`
  §1382 already names drag as the canonical reorder gesture),
- a "Set as First" button that renders even where it always rejects
  (`minimum_guided_nodes` on the tail of 3+ chains),
- a per-node connection-tree accordion (`NodeConnectionsPanel`) that duplicates
  what the Connections section already lists undirected.

P1.9 reconciles the sidebar to the spec's row model so that **P3 can stay purely
cosmetic** (P3's pinned scope: "Must not change behavior contracts, restructure the
shell" — see [`2026-08-18-P3-ui-overhaul.md`](2026-08-18-P3-ui-overhaul.md)).

It also folds in the confirmed-but-unfixed **empty-chain promotion bug**: with a
non-empty graph and an empty sequence, unsequenced cameras are unreachable — the
empty-state copy ("Drop a camera here…") is static text, every gap and "+ Insert"
affordance is gated on `guidedTourChain.length > 0`, and the validators would
reject a first insert under the D4 ≥ 2 floor. Connecting 3+ cameras must **not**
auto-promote (confirmed desired behavior), so the fix is a *manual* pair-promotion
path, not an extended seed.

## Scope

1. **Neighbor dropdown replaces the connection-tree accordion.** Sequence and
   Unsequenced rows keep their chevron, but expansion now lists the row's
   **directly-connected camera nodes** — graph truth, never reachability. Row
   content per neighbor: ① order badge when sequenced, ◯ diamond when
   unsequenced, `Branch` tag on neighbors that head an explicit Branch, click = select, eye
   = preview.
   `NodeConnectionsPanel` is deleted. Connection detail (direction, key counts,
   timing) remains available via the Connections section, the Inspector, Plan
   edges, and the Timeline.
2. **Drag-only reorder.** The per-row ↑/↓ buttons are removed from Sequence rows.
   Drag reorder (head gap = re-root, internal gaps = reorder, tail gap = append)
   is the sole reorder gesture. The `moveGuidedTourNodeIndex` helper and its unit
   tests stay (harmless; still pinned).
3. **Tail-row "Set as First" hidden** at `index === length - 1`: the button
   currently renders there on any 3+ chain where it always rejects
   (`minimum_guided_nodes`).
4. **Empty-chain promotion (bug fix).** With no flow and ≥ 2 connected
   unsequenced cameras, the Sequence Inspector empty state becomes actionable: a
   **"Start Sequence"** affordance on eligible unsequenced rows seeds a connected
   pair through the existing `seedTwoNodeFlow` machinery (one history entry,
   connected order respected). Isolated unsequenced nodes show no affordance.
   No auto-promotion on connect. The D4 ≥ 2 floor is preserved — a 1-node flow
   breaks `walkFlowChain` / the timeline, which is why the P1.8 plan deliberately
   deferred a 1-node authoring intermediate.
5. **Unsequenced relationship meta.** Unsequenced rows show "Neighbor of
   ⟨camera⟩" for direct adjacency to a sequenced camera, else "Connected to
   ⟨camera⟩" (per `Camera-flow-specs.md` §8 graph truth — never overclaim
   adjacency; a chain `C — E — F` shows F as "Connected to E", not "Neighbor of
   C").
6. **Terminology sweep (P1.8 review nit + naming reconciliation).** "kept as
   free" tooltip copy and the `free-badge` style key → Unsequenced
   wording/style keys; the sidebar section **Detours → Branches** and the
   `Branch` tag (specs and UI say Branch; the serialized field stays
   `detourOfNodeId` for schema/back-compat — no codec change).
7. **`contracts.test.ts` pins rewritten** to the new sidebar shape: the
   `interactive?` / `activeDomain` assertions on the removed panel, the
   `{activeDomain}` forwarding count, the chevron-toggle / aria-disabled counts,
   and the discovery-direction-highlight assertions all move to the neighbor-list
   shape.

## Out of scope

- **Branch rejoin** (rejoin into a later Sequence stop) — separate experiment,
  unscheduled: [`2026-08-21-branch-rejoin-experiment.md`](2026-08-21-branch-rejoin-experiment.md).
- Neighbor count chips ("1 neighbor / Branches 2") — superseded by the dropdown.
- Any P3 work (tokens, typography, palette) — P3 stays cosmetic-only.
- Visitor (`/museum`) behavior; relic behavior beyond the shared sidebar's shape
  (the relic embeds the same `CameraFlowPanel`, so it inherits the simplified rows
  with no behavior change).

## Decisions

- **Chevron stays; content changes.** "Just a dropdown collapsible." The existing
  toggle, select-on-click, preview, auto-expand-on-select, and the Plan read-only
  embed (`interactive = false` gating) all keep working.
- **`NodeConnectionsPanel` is deleted, not retained for the Inspector** — the
  Inspector already renders its own incoming/outgoing connection rows and the
  panel has no other consumers.
- **The discovery direction highlight leaves the sidebar.** It is a
  direction-edge feature; a node list has no direction. Connection detail
  (including direction and key counts) stays available via Connections /
  Inspector / Timeline.
- **Empty-state fix direction: manual pair promotion via `seedTwoNodeFlow`.**
  Rejected: relaxing D4 to a 1-node flow (breaks the timeline's ≥ 2 assumption);
  and extending the connect seed (would auto-promote, contradicting the confirmed
  desired behavior for 3+ cameras).
- **Multi-neighbor meta rule.** A row with several neighbors lists them all (up
  to two names, then "+n"); a neighbor that heads an explicit Branch shows the
  `Branch` tag instead of the relationship line (the brief's status exclusivity).
- **The collapsible extends the canonical PNG.** `camera-sidebar.png` shows rows
  without any accordion; the neighbor collapsible is a deliberate P1.9 extension
  (P3.1 logs the delta or accepts the P1.9 state — the docs are canonical).
